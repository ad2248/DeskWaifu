# 程序在常见业务流程中暴露出异常行为
当前仅通过 ctrlc::set_handler 设置退出标志，但 ctrlc = "3" 未启用 termination feature，因此不会处理 SIGTERM。执行普通 kill <pid> 或由进程管理器发送默认终止信号时，进程直接退出，无法执行 runtime.stop() 和 Server::drop()。 导致常规停止后无法直接重启，必须人工清理 socket；插件也未获得 stop() 清理机会。这并非仅发生在无法捕获的 SIGKILL 场景。

# 组件依赖

> 基线：`0058b7e`。本文区分规范要求、现行设计与证据边界：约束性措辞保留原文要求；现行行为和限制不自动升级为规范；测试描述不代表本次迁移已执行验证。

权威所有权契约见[插件架构](插件架构.md)。控制进程及其页面所有权见[GUI插件](GUI插件.md)。

生产环境所有权如下（缩进表示所有权，不表示调用关系或构建链接）：

```text
platform/main → 插件发现/生命周期 + SDK 事件循环
desktop 插件 → 私有 app/LAppDelegate（仅负责组装和生命周期）
  ├─ InteractionProcessor
  │    ├─ InteractionContext
  │    │    ├─ window/QtDesktopWindow、输出/合成器辅助对象
  │    │    └─ ApplicationService、TransformEditor、配置
  │    └─ 本地命令适配器
  ├─ ModelProcessor
  │    └─ ModelRuntime（在 model-render 上创建、使用和销毁）
  │         └─ View、Manager、模型/纹理存储、Cubism/GL 资源
  └─ InputListener + SignalProcessor
ipc 插件 → IpcProcessor → LAppIPC
  ⇄ CommandProcessor ⇄ 公开 command.<name>/v1 提供者
perception 插件 → 图像 / OCR / 截图
speech 插件 → SpeechEndpoint → 语音处理器 / 播放器 / 来源 / 音频
reading_clip 插件 → ReadingClipProcessor → 公开图像 / OCR / 语音能力
```

插件不得编译、链接、包含或调用其他所有者的实现，即使通过 Delegate 或注入业务回调也不允许。强耦合的模型/窗口/输入辅助对象在 desktop 内部协作。处理器内部事件使用 `ProcessorEvent` 值和不透明的 `IProcessorPlugin*` 回复路由；跨插件请求使用 SDK 端点和公开能力。LAppIPC 调用由其所属 IpcProcessor 实现的 `ICommandService`；该接口不是一个独立所有的服务。IpcProcessor 与 CommandProcessor 交换 `command.request` / `ipc.command.result`。Command 仅通过 `command.<name>/v1` 路由，返回明确的提供者错误，不回退到内置领域实现。Desktop 的适配器先通过 interaction 检查模型请求，再携带原始发送者转发 `model.operation`。Command 拥有协议队列，不拥有 GUI、配置、OCR 或模型状态。Interaction 从 `model.state` 缓存模型元数据。读取功能通过其插件端点使用 `image.read/v1`、`ocr.recognize/v1` 和 `speech.speak/v1`。请求 ID、取消和超时不同于插件内处理器回复路由。

构建链接与上述所有权/事件图不同。`deskwaifu` 只编译平台启动/配置代码，链接平台插件宿主及 SDK/Qt。它不编译 QtDesktopWindow，也不链接业务实现。`desktop_plugin` 编译 desktop 入口及 Qt 窗口，链接其私有的 `deskwaifu_application` 和辅助库。Perception、IPC、speech 和 reading 的实现分别链接到各自模块。禁止跨所有者调用的规则也在构建边界（包括测试）上执行，参见[根 CMakeLists](../../CMakeLists.txt)及各插件本地 CMakeLists。独立的控制进程加载 GUI 入口；其标签页属于 `plugins/<name>/gui/`，不属于 MainWindow。

处理器事件处理器在 GUI 线程运行；ModelProcessor 是 GUI 侧代理。工作线程定时器在 `model-render` 上驱动 ModelRuntime，不使用逐帧业务事件。GUI 呈现上传 CPU RGBA 帧。图像快照在 GUI 线程读取，通过 QtConcurrent 编码；OCR 在子进程运行。

Desktop 私有的 `processor/model/ModelExchange` 是有界的“最新输入/最新不可变帧”槽，不是服务端口。跨 GUI/模型边界的本地 `ModelHitTest` 回调弱引用 CPU 快照邮箱，不能访问处理器、Cubism 或 GL。这些渲染、命中测试和透明度区域算法不是安装后的 SDK 契约。连续指针采样也使用有界槽；离散输入是屏障。

平台在停止任何插件之前，先使全部插件上下文失效。每个插件停止自己的来源和任务；desktop 在销毁模型代理和关闭窗口前等待模型线程结束。图像编码及 OCR 子进程在释放其资源引用前结束。历史遗留、仅用于测试的生命周期/悬停辅助对象副本位于所属插件的测试目录，不在 SDK 或生产实现中。

`processor-boundaries` 包含直接/相对跨领域包含、前置声明具体对等类、Delegate 访问及已知回调绕行的负向样例；它不是完整 C++ 调用图或任意回调安全性的证明。`processor-ownership` 使用私有套接字、合成图像数据和公开模型/语音能力测试替身，测试真实动态加载的 IPC/OCR/reading 模块；`desktop-ownership` 保留原生输入、编辑守卫及会话释放覆盖。`reading-plugin` 单独加载真实 reading/perception 模块和语音能力测试替身。`model-render-thread` 提供契约中真实 Cubism/GL 部分的验证。宿主、端点和 GUI 测试覆盖各自的路由/生命周期边界，单靠处理器测试替身不能证明这些边界。

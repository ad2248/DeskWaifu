# 模型窗口状态机

> 基线：`0058b7e`。本文区分规范要求、现行设计与证据边界：约束性措辞保留原文要求；现行行为和限制不自动升级为规范；测试描述不代表本次迁移已执行验证。插件所有权以[插件架构](插件架构.md)为权威。

`plugins/desktop/private/processor/interaction/ModelWindowState` 使用 Qt State Machine（`QStateMachine`、`QState` 和 `QAbstractTransition`）控制生命周期与输入策略。活动 Qt 状态配置是窗口策略的事实来源，没有并行的窗口生命周期枚举。`InteractionProcessor` 另有 `_stopped` 标志，独立于状态机控制其输入和操作处理。

```text
Uninitialized -> Initializing -> Running
                                |-- Normal
                                |   |-- NormalIdle
                                |   `-- Pressed
                                |-- ScreenEditing
                                |   |-- EditIdle
                                |   |-- DraggingModel
                                |   |-- MovingCrop
                                |   `-- ResizingCrop
                                `-- PanelEditing
Running -> SwitchingOutput -> Running
Uninitialized / Initializing / Running / SwitchingOutput -> Closing -> Closed
```

## 输入与编辑

- 普通按下/释放使用延迟点击和双击识别器。移动超出阈值会启动本地屏幕编辑事务并进入 `ScreenEditing/DraggingModel`。没有单独的普通拖动状态，因为拖动会打开编辑器。
- 屏幕编辑时，命中测试选择移动模型、同时移动模型和裁剪，或调整裁剪边缘/角点大小。所选边缘/角点是手势数据，不是另一个状态。释放通常返回 `EditIdle`；外部点击和裁剪框双击尝试应用草稿。应用成功结束编辑，失败则保留事务。
- `PanelEditing` 表示仅控制面板使用的事务。它拒绝模型鼠标按键、滚轮和键盘操作，但允许 IPC 事务更新。此模式不阻止指针位置和悬停跟踪。
- `TransformEditor` 拥有草稿/提交/取消及连接所有权。其同步编辑变化回调在 `Running` 时同步输入模式，涵盖断开连接及成功应用、取消、重置、重新加载/丢弃。输出更换期间，模式同步等待更换完成。`TransformEditor` 不依赖 Qt。
- 离开模式会清除手势数据、待处理点击和键盘捕获。帧尺寸变化及成功隐藏也会取消已捕获的手势。帧尺寸变化还取消屏幕编辑事务；隐藏不会保存或取消编辑事务。

## 输出变化与拆除

窗口后端在嵌套的窗口暴露等待之前报告 `OutputSwitchStarted`，在成功或回滚之后报告 `OutputSwitchFinished`。更换期间策略拒绝输入。后端 `_switching` 守卫局限于表面更换，防止嵌套渲染或第二次表面更换。

本地跨屏移动取消手势但不取消草稿，保持显式保存行为。编辑期间拒绝通过控制命令显式选择显示器。热插拔重新绑定会取消任何编辑事务，包括仅面板编辑。更换后从编辑器恢复模式，不恢复已捕获手势。等待期间收到的关闭不能被完成通知撤销。

应用退出进入 `Closing`。初始化失败返回调用者，不一定进入 `Closing`：窗口启动失败可能使策略留在 `Initializing`，后续应用启动失败可能使其留在 `Running`。调用者的释放路径停止 interaction 并进入 `Closing`。有序拆除先停止模型工作线程，再关闭窗口。随后窗口关闭发送 `Released` 并进入 `Closed`，即使模型 GPU 清理失败也是如此。释放仍报告该失败；`Closed` 不证明 GPU 清理或上下文恢复成功。

## 派发与测试

调用运行在应用的 Qt 线程，并有 `QCoreApplication` 存在。`Send` 投递策略事件，并仅排空状态机已投递的元调用事件。这使同步输入/IPC 处理器继续前提交转换，而不处理无关应用事件。取消回调仅重置手势/平台数据，不得递归派发策略事件。

`model-window-state` 测试真实 Qt 状态图、非法事件、取消、从启动/运行/切换状态显式关闭与释放的转换，以及不派发无关事件循环事件。它不注入实际启动或 GPU 清理失败。

`model-pointer-state` 使用隔离的 EGL 窗口边界测试生产 Delegate、编辑器及模型输入，涵盖裁剪移动/缩放、面板事务、过期释放、切换期间输入、热插拔及切换期间关闭。该边界模拟输出更换，不测试 Qt 后端嵌套的窗口暴露等待和回滚。`model-shutdown-context` 检查模型工作线程清理失败及避免不安全 GL 删除，不检查应用窗口最终策略状态。其他指针、键盘、编辑和拆除测试仍适用。

## 需求验收与证据边界

- 按状态图核对输入、编辑事务、切换及关闭转换，区分手势取消和事务取消，确认关闭不会被切换完成通知撤销。
- 核对同步派发不处理无关事件，取消回调不递归派发。
- `Closed` 仅表示窗口策略状态，不作为 GPU 清理成功证明；状态图测试、模拟窗口边界与真实后端/GPU 测试的证据不得互相替代。

# Arch 二进制发布

工作流由 tag 推送或手动运行触发，使用 `deskwaifu-rust` runner。源代码来自精确 tag 对应提交的 `git archive`。手动运行若填写的 tag 不存在且未启用 `notes_only`，工作流会从 `origin/main` 的顶端提交创建并推送该 tag。Tag 推送会核对事件提交。发布工具在检出源码前保存到 checkout 外的独立目录，由 `RELEASE_TOOLS_DIR` 指定。 [发布工作流](<../../.gitea/workflows/release.yml>) · [标签选择脚本](<../../scripts/release-source.py>)

手动运行必须填写非空 `release_notes`，该内容完整用作 GitHub Release 正文。`notes_only` 仅更新已发布且 tag 匹配的 Release 正文，不构建或改动资产。Tag 推送用默认正文创建 Release，已存在的正文保留。Tag 原样用于 Arch `pkgver` 与 GitHub Release，使用符合 Arch 版本规则的 tag。 [上传工具](<../../scripts/release-upload.py>)

## 构建与产物

发布生成一个 `deskwaifu-bin` 包、`SHA256SUMS` 和 `release-metadata.json`。工具按所选提交的 Cargo workspace 声明选定支持的载荷，并校验包身份、内容和校验和。带原生 `terminal` 和控制面板的载荷需要外部 Cubism SDK 与 GLEW，只安装 Cargo 生成的运行产物。发布这一载荷前须确认再分发权并设置 `DESKWAIFU_CUBISM_REDISTRIBUTION_APPROVED=1`。 [包布局、受支持载荷与依赖](<../../packaging/release/README.md>)

root runner 使用独立临时账户运行 Cargo 依赖获取和 makepkg。正式发布使用独立 Cargo 缓存，编译阶段使用离线依赖。临时账户应无法修改 checkout 及可信工具目录。 [构建入口](<../../scripts/release-build.sh>)

## 上传与重试

仅上传步骤获得 `RELEASE_UPLOAD`，该 GitHub token 需要 `ad2248/DeskWaifu` 的 Contents 读写权限。GitHub 必须拥有同一源提交。工作流可为该提交创建缺失的 GitHub tag，已有 tag 必须解析到同一提交。 [发布工作流](<../../.gitea/workflows/release.yml>) · [上传工具](<../../scripts/release-upload.py>)

缺失 Release 时先建 draft，验证 tag 和全部资产后公开。重试时复用摘要一致的资产，同名资产内容不一致会失败。构建可复现性须另用相同环境独立构建并比较结果。发布后可更新 AUR 子模块。 [发布验证入口](<../../packaging/release/README.md#verification>) · [AUR 打包与维护](<AUR打包与维护.md>)

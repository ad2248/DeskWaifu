# 测试与门禁

[Rust CI](<../../.gitea/workflows/ci.yml>) 的 `test` 作业执行格式检查、debug 与 release 工作区构建、Clippy、Rust 工作区测试（含软件 EGL 离屏用例）和 Python 工具测试。`package` 作业归档当前提交，以非 root 账户构建 Arch 包，安装后核对宿主链接、插件、控制面板和 CLI 命令注册。复现 CI 时使用相同固定镜像和 Cargo vendor 配置。 [CI 运行器](<CI运行器.md>)

## 本地检查

准备工作区的系统依赖和 Cubism/GLEW 后，在仓库根运行。 [构建依赖](<构建依赖.md>)

```sh
cargo fmt --all --check
cargo build --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
env -u DISPLAY -u WAYLAND_DISPLAY -u CUBISM_TEST_PCI -u CUBISM_TEST_SECOND_PCI \
  LIBGL_ALWAYS_SOFTWARE=1 cargo test --workspace --locked
cargo build --workspace --locked --release
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
python3 -B -m unittest discover -s .gitea/scripts -p 'test_*.py' -v
```

## 验收边界

- Rust IPC 测试使用私有 Unix socket 检查信封、分帧、背压和清理。平台进程使用固定路径，验证前应确认测试环境没有用户进程或用户 socket。 [传输测试](<../../crates/os/tests/ipc.rs>)
- 软件 EGL 检查真实 Cubism 渲染与像素。指定 PCI、跨 GPU、合成器输入区域及实际窗口表现须分别验收。桌面检查使用私有合成器。 [渲染与设备测试](<../../crates/cubism-bridge/README.md>)
- 录音、剪贴板和 ASR 测试分别覆盖隔离会话或本地服务。物理麦克风、实体桌面和真实云端账户需要各自环境。 [语音输入验收入口](<../语音输入.md#验收范围>)
- 打包工具回归使用夹具验证发布权限、资产与安装契约。真实 CI 包的安装验证来自 `package` 作业。 [打包测试](<../../packaging/release/README.md#verification>)

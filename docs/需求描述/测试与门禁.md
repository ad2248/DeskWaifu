# 测试与门禁

> 核对基线：`0058b7e`。本页是现行测试要求与操作入口；记录已定义的测试，不声明本次全部运行。历史实验、发现与旧计数见[回归门禁设计与实验](../实施日志/回归门禁设计与实验.md)及[测试归属迁移](../实施日志/测试归属迁移.md)。

## 目标与非目标

按产品承诺解释证据，按环境能力执行测试。不以数量、源码字符串或一次成功替代行为覆盖；继续使用 CTest、QtTest、Python，不自建万能事件/Socket/EGL 模拟框架。普通软件门禁不自动授权真实云、发声设备、私有模型、指定 PCI 或用户桌面操作。

## 需求与完整配置

- **TEST-01**：完整门禁必须启用 `BUILD_TESTING`、`DESKWAIFU_BUILD_CONTROL`、全部六个后端插件（DESKTOP、PERCEPTION、IPC、SPEECH、READING_CLIP、VOICE_INPUT）以及 `DESKWAIFU_TEST_GATE`；缺失任一前置条件须配置失败。根工程还需要 Python，普通测试需要 `dbus-run-session`，完整门禁另需 Node。权威开关定义在[根 CMakeLists](../../CMakeLists.txt)。
- **TEST-02**：普通 CI 与下列入口显式关闭原生 OCR helper；默认源码构建仍开启 OCR。故障植入的新建 CMake 工程也必须独立指定关闭，不能假设继承父缓存。真实 OCR 模型与引擎另走[原生 OCR 入口](../../plugins/perception/native/README.md)。
- **TEST-03**：`tests/gate.json` 校验关键注册入口，实际注册的全部测试都执行，不能任意跳过清单外新测试。设备/授权例外精确到进程或 QtTest 子用例并输出 UNVERIFIED；其他 skip 使完整门禁失败，不能放宽整个套件以修绿 CI。
- **TEST-04**：CTest、Sway、KWin 阶段顺序执行；普通 CTest 门禁内部以 12 路并行运行，CI 构建（含渲染变体、Sanitizer 和故障植入）使用 24 路编译，不以串行或自动重试掩盖实例冲突。必需平台能力缺失必须失败，不能返回 77 涂绿。`kwin-cursor-locale` 原有无法创建私有 locale 的 77 仍会让完整门禁失败；指定设备 offscreen 的已允许未验证与普通失败必须分开。
- **TEST-05**：有行为风险的修复需复现用例；关键入口保护可加入 gate.json.required，并设计针对性故障，证明指定断言失败、恢复后通过。直接编译和普通 ctest 不代表故障植入、渲染变体、平台 smoke 或 sanitizer 已通过。PR 上故障植入按改动路径选择：只有可能影响某故障的生产文件、其对应测试源文件、该测试目标链接或包含的应用源码，以及该测试目标编译的辅助头文件（如 `ModelProcessorTestHelpers.hpp`、`TestApplication.hpp`、`EventLoopFence.hpp`）发生变化时才执行该故障，改动落在故障构建共同依赖的路径（根 `CMakeLists.txt`、`cmake/`、`platform/`、`sdk/`、`thirdParty/`）时执行全集，无法取得 diff 时执行全集或失败，不静默降级为子集。每个故障的依赖必须显式声明，不能依赖“未映射 → 全集”作为隐式兜底。选中为空时只报告“无相关改动”，选中非全集时报告显式标注 PARTIAL，不能当作全集通过证据。

## 本地操作入口

需要 Linux、CMake 3.25+、Ninja、Python、Qt/LayerShellQt、Mesa llvmpipe、D-Bus、Node、Wayland scanner、Cubism/GLEW。平台 smoke 另需 Sway/swaymsg、wayland-info、kwin_wayland，1.5 倍缩放需 kscreen-doctor。命令从仓库根运行，替换外部依赖路径：

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON -DDESKWAIFU_BUILD_CONTROL=ON -DDESKWAIFU_TEST_GATE=ON \
  -DDESKWAIFU_BUILD_OCR=OFF \
  -DSDK_ROOT_PATH=/path/to/CubismSdkForNative-5-r.5 -DGLEW_PATH=/path/to/glew
cmake --build build --parallel 24
python3 scripts/run-test-gate.py build
DESKWAIFU_DEPS_DIR=/path/to/deps bash scripts/headless-smoke-test.sh build
python3 plugins/desktop/tests/qt_headless_smoke.py build /path/to/CubismSdkForNative-5-r.5
python3 plugins/desktop/tests/qt_headless_smoke.py build /path/to/CubismSdkForNative-5-r.5 --scale 1.5 --installed
python3 scripts/test-environment.py python3 scripts/check-test-mutations.py build
# 可选：只跑某次改动可能影响的故障，传入待比较的基线提交
python3 scripts/check-test-mutations.py build --base origin/main
```

`--base` 取该提交与本分支的共同祖先（merge-base）作为基线，所以传基线分支的当前 tip 也是安全的：基线分支在分叉之后新增的提交不会被算作本分支的改动。浅克隆的 graft 边界会被 git 当成 merge-base 并静默给出空 diff，因此浅克隆下脚本直接报错退出，不做子集选择；需要选择能力时用完整历史（CI 中 `fetch-depth: 0`）。

定向诊断可在 run-test-gate.py 后增加 `--test '^interaction-opacity$'` 等过滤器，不能把子集报告当完整通过。渲染目标变体、Debug ASan+UBSan 的配置/目标/筛选以[CI 工作流](../../.gitea/workflows/ci.yml)为准；声明“与 CI 一致”需要相同固定镜像、新构建目录和全部工作流步骤。历史遗漏的因果链见[CI 556 分析](../实施日志/CI-556失败分析.md)。

## 能力与证据边界

| 能力 | 执行要求 | 不证明什么 |
| --- | --- | --- |
| 根 CTest、插件/SDK/GUI 契约 | 每 PR 全部已注册场景；真实 Qt 循环、线程、socket、加载器，本地服务夹具 | 真实云、发声和 OCR 准确率；offscreen 页面不等于真实桌面 |
| 语音取消/替换、透明度、光标、模型线程及收尾 | 每 PR；故障植入覆盖关键生产断言，PR 按改动路径选择、全集作为默认 | 测试副本不等于生产策略；source/audio 替身不证明云或设备 |
| OCR client | 根 CTest；生产客户端与真实子进程协议，OCR 引擎替身 | 没有下载模型，不证明推理精度 |
| AUR 元数据 | 根 CTest | 不是 makepkg 安装或干净系统依赖验证 |
| Sway smoke | 每 PR；私有双输出与真实应用/IPC/控制端 | 无键盘 seat，不证明 KWin 焦点与真实点击路由 |
| KWin scale 1、1.5 | 每 PR；私有合成器、layer-shell、像素、焦点、热插拔、点击路由 | 软件驱动/虚拟输出，不证明物理桌面或所有硬件 |
| KWin 1.5 `--installed` | 每 PR；私有 prefix，三条已安装命令、控制端 smoke | CLI 继承启动目录，不能声称其脱离源码运行；不安装可选 OCR 模型/组件 |
| 两种 render-target 编译分支 | 每 PR 编译正式应用目标 | 编译不等于两条路径像素均执行 |
| ASan+UBSan | 每 PR Debug 核心契约子集，UBSan 不恢复；溢出夹具证明失败传播 | 预编译 Cubism Core 未插桩，不覆盖所有 Qt/GL/线程问题 |
| 指定 PCI/跨 GPU | 专用 runner 或维护者发布前显式授权，附 PCI、驱动和窗口 GPU | 普通 auto/软件场景不能替代 |
| 真实音频/云 API/私有模型 | 专用授权入口，不因继承环境自动开启 | 不是普通软件 PR 的阻塞前提；原记录的音频专项仍需独立交付核验 |

具体行为依据见对应需求主题。语音契约使用真实状态机但替换 source/audio；`reading-plugin` 加载真实 reading/perception 并使用语音能力夹具；`speech-plugin-load` 单独补真实语音模块加载。GPU 测试检查真实 Cubism/EGL、纹理 ID、线程与 context，不证明所有 shader/FBO 或物理 context-loss。透明度策略与 compositor 真实穿透分别验收，不能互相冒充。

## 测试归属

根普通入口为 `platform/tests/CMakeLists.txt`。领域专用的 C++、Python、JavaScript、CMake 检查与 smoke 夹具统一归所属 `plugins/<owner>/tests/`，由插件本地 CMake 注册；原生 OCR 模型契约由 perception 的原生构建入口注册。根 `tests/` 只保留仓库级架构边界、打包、文档和测试基础设施门禁。宿主链接检查归 `platform/plugin/tests/`，共享临时目录检查归 `platform/tests/support/`。platform 集成只通过 SDK/公共协议和 test-only 模块控制边界，不能放宽构建防火墙包含对端私有实现。

`processor-pipeline` 聚合领域适配器及 perception/reading 链路；`processor-ownership` 动态加载 IPC/perception/reading，desktop 私有输入/编辑与释放由 `desktop-ownership` 保留。GUI tabs 动态加载页面而非编译业务源码，主题测试通过公开宿主消息填充控件；设置、语音和重启夹具由对应插件拥有。`platform/tests/support` 只供平台集成使用。

`build-boundaries-*` 的真实 C++ 小工程验证跨源文件、链接、绝对/相对/尖括号 include、对象归档、PCH 与合法消费者；不依赖 Qt/Cubism，不是完整 C++ 调用图或恶意代码沙箱。每个 unittest 方法独立注册为隔离的 CTest，参与 12 路调度，保留方法内全部参数组合，不再让整套案例共用一个限时。`build-boundary-registration` 对照实际 unittest 方法检查注册和必需入口清单，防止遗漏或退回串行聚合入口。定向验证使用 `python3 scripts/run-test-gate.py build --test '^build-boundaries-'`。架构权威见[插件架构](插件架构.md)。

## 隔离、产物与维护

- **TEST-06**：每个普通 CTest 入口使用 `deskwaifu_add_test` 注册，逐项调用 `test-environment.py`，不在整个 CTest 外层共享一套环境。环境白名单创建私有 HOME/runtime/config/cache/data/tmp 与 D-Bus，移除继承桌面 socket、插件覆盖、凭据及付费/发声开关；GLVND 显式选择 Mesa vendor JSON。CI 提供的 `GITHUB_STEP_SUMMARY` 与夹具所需的 `DESKWAIFU_DEPS_DIR` 一样按需转发（变量为空时不写入），否则报告脚本在被隔离的子进程里根本看不到 job summary 文件。夹具必需的插件路径等使用注册函数的 `ENVIRONMENT` 参数在隔离后显式设置，不扩大宿主环境白名单。退出/失败/中断只清理自己的进程组和目录。它不是网络/文件系统沙箱，测试仍须使用合成输入和本地边界。显式授权的真实 Wayland 测试仍使用原生 `add_test`，不进入普通隔离入口。
- 普通测试不设置 CTest 或隔离包装器的执行超时；测试失败仍按退出状态判定，包装器在退出后清理自身进程组和私有目录。需要超时语义的专项测试必须在测试自身或独立的受控入口中声明，不由通用测试环境包装器隐式截断。
- `WILL_FAIL` 由隔离包装器内部在实际命令启动后处理，CTest 不反转包装器本身的退出状态；`SKIP_RETURN_CODE` 仍按原规则单独判定。安装测试导出与执行同样保留这些语义。
- 隔离根固定建于 `/tmp/opencode`（存在时）或 `/tmp` 下，不继承外层 `TMPDIR` 作为父目录，避免安装测试嵌套包装后 Unix socket 路径超长；每项仍有独立且退出清理的私有临时目录。
- 四包安装阶段保持既定安装顺序；每个测试包内部以 12 路执行，各自启动隔离包装器。导出安装清单时剥离源码包装器并保留其显式环境，不导出或执行隐式时间预算。CI 的可复现包构建通过 `CMAKE_BUILD_PARALLEL_LEVEL=24` 使用同一发布构建入口。
- CI 编译中间结果经 ccache 持久化到运行器宿主机缓存卷；`workflow_dispatch` 的 `clean` 选项关闭本次缓存使用（不清空共享缓存）。缓存不改变编译输出与门禁语义；缓存卷缺失时自动回退无缓存构建。CI 只构建一次四包产物，不再对同一提交做第二次独立构建并比较字节，因此 CI 不证明构建可复现；需要该结论时按[发布打包](发布打包.md)另行核查。
- `test-environment` 以并发屏障验证十二项 CTest 的目录及 D-Bus 地址独立，并验证直接 CTest 与门禁两种入口；`backend-multi-instance` 同时运行两个真实平台/IPC 插件，确认标准环境变量控制各自目录、对端 PID 正确、退出一个不影响另一个。这里验证不同运行目录的多实例，不声明同一运行目录的固定 IPC 端点可被多个实例共用。
- 不删除用户 runtime 中的 Wayland/应用 socket；启动并发测试只检查同 UID、同运行目录的后端。若当前运行目录已有用户桌宠，使用私有 PID/user namespace 和 proc 视图，不能停止用户进程；隔离不可用则明确失败。其他独立运行目录的并行后端不应触发 namespace 权限要求。
- 完成报告流程时，门禁在 `BUILD/test-logs/ctest-*/` 留存 registry.json、ctest.xml、ctest.log、summary.json，区分进程 passed 和内部 partial/UNVERIFIED，保留原因与耗时。直接 ctest 或提前中断不保证这组产物齐全。
- 输出截断不得作为全部子用例覆盖证明；诊断重跑另存，不能覆盖首次失败。KWin 产物在 `BUILD/qt-smoke-logs/<scale>/run-*/`，Sway 在 `BUILD/test-logs/sway-*/`；installed 才有安装日志。
- 故障植入在受控源副本进行，文本产物位于 `BUILD/test-logs/mutations/run-*/`；内层结构化 CTest 产物随临时构建删除，不能声称完整留存。本次选择（是否全量、合并基准、改动路径、选中项与原因）另写固定路径 `BUILD/test-logs/mutations/selection.json`，因此 `selected: 0` 的跳过路径也有可核对的记录，同时写入 job summary。失败时上传文本，通过时不上传以省去固定的打包与上传开销；上传内容不得包含 SDK、私有模型、二进制、环境全量或凭据。
- 新图像差异/随机测试记录合成输入、独立期望与种子，先核查隐私。共享设施经实际复用再提取；FIFO fence 只约束明确已投递事件，不能等待未来 worker/socket 或替代任意 sleep。

CI job 的 30 分钟是配置时限，不是实测耗时。旧计数、单机耗时或一次成功不能推出当前覆盖率、p95、误报率或资源上限，预算需由维护者根据多次真实报告调整。

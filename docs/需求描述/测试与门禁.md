# 测试与门禁

[Rust CI](<../../.gitea/workflows/ci.yml>) 分两段串行：`build` 作业在 `deskwaifu-rust` 上编译整个工作区并打出 Arch 包，写入 `st` 上的共享目录 `/transfer/<run>-<sha>/`；`test` 作业在 `deskwaifu-gui` 上校验该目录、安装包，再对它运行验收用例。包只在共享目录中传递，artifact 只承载日志与测试记录。 [CI 运行器](<CI运行器.md>) · [共享目录约定](<../../关键设计/ci.md#43-共享目录约定>)

`test` 只接触安装后的文件，不编译 Rust。验收用例位于 [tests/acceptance](../../tests/acceptance)，入口是 `run_suite.py`：它先安装包并把过程写进 `install/安装/`，再逐个运行注册的用例。

## 本地检查

CI 不再执行静态检查与单测，改动后请在本地自行运行。准备工作区的系统依赖和 Cubism/GLEW 后，在仓库根运行。 [构建依赖](<构建依赖.md>)

```sh
cargo fmt --all --check
cargo build --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
env -u DISPLAY -u WAYLAND_DISPLAY -u CUBISM_TEST_PCI -u CUBISM_TEST_SECOND_PCI \
  LIBGL_ALWAYS_SOFTWARE=1 cargo test --workspace --locked
cargo build --workspace --locked --release
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
python3 -B -m unittest discover -s .gitea/scripts -p 'test_*.py' -v
```

## 验收框架

```sh
python3 -B tests/acceptance/run_suite.py --list                 # 列出用例
python3 -B tests/acceptance/run_suite.py --package-dir <目录> --output <记录目录>
python3 -B tests/acceptance/run_suite.py --bin-dir target/release --output <记录目录>  # 本机调试，跳过安装
```

- 记录目录必须尚不存在；套件创建它，退出码 `0` 全通过、`1` 有失败、`2` 参数或环境错误。
- 新增用例：在 `tests/acceptance/cases/` 新增模块，提供 `CASE`（`id`、`title`、`requires`）与 `run(context)`，并加入 `cases/__init__.py` 的注册表。`requires` 含 `session` 的用例由 `session.py` 在私有 Plasma 会话中重新调用。
- 记录布局：

```
<记录目录>/
├── summary.json                  # 安装与每个用例的汇总状态
├── install/安装/                 # 依赖预检、pacman 日志、已安装文件与摘要
└── <用例标题>/
    ├── result.json               # 用例级结果与步骤状态
    ├── session.log               # 需要 Plasma 会话的用例
    └── <步骤名>/{result.json,stdout.log,stderr.log,screen.mp4}
```

- 每个步骤记录动作输入、预期、观察到的结果、状态与相关日志；未执行的步骤记为 `not_run` 并写明原因。安装失败时所有用例记为 `not_run`，套件仍写出 `summary.json`。

## GUI 在无守护进程情况下启动关闭

用例 `gui_panel_open_close` 在隔离容器和私有 Plasma 会话中运行。它不启动 DeskWaifu 宿主，只启动安装包提供的 `deskwaifu-terminal-panel`，并为面板指定一个不存在的私有 socket。依次确认 KWin 报告控制面板窗口出现、同一个窗口消失，每步录制 15 fps H.265 视频。 [GUI 用例](<../../tests/acceptance/cases/gui_panel_open_close.py>)

使用具备相同依赖和 DRM 渲染节点权限的隔离容器复现：

```sh
python3 -B tests/acceptance/run_suite.py --bin-dir target/debug \
  --output target/test-records --case gui_panel_open_close
tar --zstd -cf target/test-records.tar.zst -C target/test-records .
```

从 Gitea 运行页下载 `test-records`，取出其中的 `test-records.tar.zst`。包内目录为 `./GUI在无守护进程情况下启动关闭/启动` 和 `./GUI在无守护进程情况下启动关闭/关闭`。视频规格在下载后使用 `ffprobe` 核验，不由 CI 判断。

## 产物

| artifact | 内容 |
| --- | --- |
| `ci-build` | `build.log`、`toolchain.txt`、`SHA256SUMS`、`release-metadata.json`、`SHA256SUMS.check.log` |
| `test-records` | `summary.json`、`install/`、各用例目录与录制视频 |

两个 artifact 保留 30 天，失败时也上传已产生的部分。CI 在用例失败时仍归档记录，作业保持失败。

## 验收边界

- 宿主冒烟测试通过固定 Unix socket 用 CLI 调用动态插件。请在没有用户宿主进程或用户 socket 的隔离环境中运行。 [宿主冒烟测试](<../../apps/deskwaifu/tests/smoke.rs>)
- 软件 EGL 检查真实 Cubism 渲染与像素。指定 PCI、跨 GPU、合成器输入区域及实际窗口表现须分别验收。桌面检查使用私有合成器。 [渲染与设备测试](<../../crates/cubism-bridge/README.md>)
- 录音、剪贴板和 ASR 测试分别覆盖隔离会话或本地服务。物理麦克风、实体桌面和真实云端账户需要各自环境。 [语音输入验收入口](<../语音输入.md#验收范围>)
- 打包工具回归使用夹具验证发布权限、资产与安装契约。真实 CI 包的安装验证来自 `test` 作业的安装阶段。 [打包测试](<../../packaging/release/README.md#verification>)

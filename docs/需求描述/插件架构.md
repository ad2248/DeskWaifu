# 插件架构

宿主从实际可执行文件相邻的 `plugins/` 目录加载 `*.so`，按文件名排序。当前工作区提供 `terminal`、`voice_input` 和测试命令插件。Arch 包把宿主和插件安装在 `/usr/lib/deskwaifu/` 下。本地开发先构建工作区，再部署对应 profile 的插件。 [动态加载实现](<../../crates/runtime/src/lib.rs>) · [构建与部署](<构建依赖.md>)

动态入口为 Rust ABI 的 `deskwaifu_plugin_create() -> Box<dyn Plugin>`。宿主和插件使用同一份源代码与同一 Rust 工具链一起构建。插件在宿主权限下运行，部署时只加载可信代码。加载发生在启动时，退出时停止插件并释放库，替换文件后应重启宿主。 [SDK 契约](<../../crates/sdk/src/lib.rs>)

## 生命周期与路由

- `initialize` 登记命令、面板标签页和类型化订阅。初始化失败时撤销该插件的注册并尝试清理。初始化结束后激活通信并启动成功初始化的插件，启动完成才开始派发。
- `Context::register_command` 登记命令名与帮助。命令名必须唯一，`help` 和 `panel-tabs` 保留给运行时。IPC 按注册名调用 `Plugin::on_command`。类型化发布订阅独立处理广播，发布成功代表入队。
- 回调在运行时线程串行执行。插件可登记非零周期或通过 `Context::spawn_local` 提交异步任务。阻塞任务归插件自己的工作线程，停止时由插件回收。
- 宿主关闭时使上下文失效，清理待决消息和宿主任务，再逆序停止插件。插件启动、周期或消息处理返回错误时进入同一清理流程。 [运行时](<../../crates/runtime/src/lib.rs>)

## 面板与系统服务

GPUI 面板为独立进程，经 `panel-tabs` 获取声明式页面，通过现有命令和查询与宿主交互。插件可经 `Context::os()` 使用宿主提供的异步系统服务，例如录音和剪贴板。插件的共享配置以其 ID 为键，由各插件定义字段。 [控制面板](<../../apps/terminal-panel/README.md>) · [系统服务](<../../crates/os/src/services.rs>) · [配置与保存](<配置与保存.md>)

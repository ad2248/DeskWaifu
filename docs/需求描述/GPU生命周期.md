# GPU 所有权与拆除（#81）

> 基线：`0058b7e`。本文区分规范要求、现行设计与证据边界：约束性措辞保留原文要求；现行行为和限制不自动升级为规范；测试描述不代表本次迁移已执行验证。插件所有权以[插件架构](插件架构.md)为权威。

纹理存储拥有模型 GL 纹理对象。模型拥有以资源路径为键、只能移动的 `TextureResidency::Lease` 值；renderer 仅在租约存活时借用数值 ID。第二个模型引用完全相同的路径字符串时增加一个引用，不会再次上传 GPU；路径别名不做规范化。最后一个租约调用 `glDeleteTextures`。被检测到的部分加载失败，会在销毁部分构建的模型时释放租约。读取/解码失败和零纹理 ID 会被检测，但上传和 mipmap 的 GL 错误不被检查。重建 renderer 复用模型已有租约。View 的离屏目标和精灵在模型之前销毁；纹理存储的生命周期长于所有借用租约。

模型会话对缓存模型纹理占用采用 **128 MiB 软预算**（RGBA8 基础层：宽 × 高 × 4）。加载期间可以暂时超出预算，单个超预算的活动模型仍固定保留。除此以外会丢弃非活动缓存模型，必要时也丢弃预取的下一个模型。共享路径时采用有意保守的计数；纹理存储报告去重后的基础层估算值，且**不保留没有租约的模型纹理**。这些估算不是实际显存用量：不包括生成的 mipmap、渲染目标、SDK 内部资源和驱动开销。另有独立规则：模型目录超过四项时，在预取之前丢弃所选和下一个模型之外的全部模型，不受字节预算影响。

模型拆除在 **model-render 工作线程**运行，并恢复其自身离屏上下文：默认使用 Qt，显式选择设备时使用 EGL，而不是 GUI 窗口的呈现上下文。运行时成功拆除按 View、模型/会话、纹理存储、Cubism 框架的顺序销毁；随后渲染目标释放 FBO 和上下文。GUI 窗口资源在此之后关闭。准备失败不会创建工作线程；一旦工作线程存在，即使初始化失败，也会在 Stop 期间尝试绑定上下文。

如果运行时上下文恢复失败，Stop 报告失败，将 View、manager/session 和纹理存储留给进程清理，并跳过 Cubism 清理。渲染目标仍尝试自身独立关闭。无法绑定的 Qt 目标放弃清理其 FBO，但销毁上下文；关闭失败的 EGL 目标被整体放弃清理。GUI 窗口仍继续关闭，绑定成功则删除 FBO，否则放弃清理 FBO，随后销毁上下文和窗口。

无头 Wayland CI 定义了带退出码和拆除日志断言的 `quit` IPC 冒烟测试；它允许一条特定的已知 SDK `glDeleteProgram` 诊断。`texture-residency` 和 `model-session` 定义租约/计数及软预算检查。`model-render-thread` 和 `model-shutdown-context` 使用真实 Cubism 及软件 EGL 并注入失败，观测正常关闭、部分初始化、运行时恢复失败时的实际纹理操作及线程/上下文身份。它们不证明每个着色器/FBO 操作、完整析构顺序或物理上下文丢失后的恢复。这些是测试定义，不表示本次文档更新执行过测试。

## 需求验收与证据边界

- 核对租约引用与最终释放、软预算保留活动模型及工作线程拆除路径；区分成功清理和放弃清理后由进程回收。
- 上传/mipmap GL 错误未检测是现状限制，不将其改写为允许忽略错误的规范，也不宣称已经具备检测能力。
- 验收证据限于相应测试实际观察的操作与上下文，不外推为所有 GPU 操作或物理上下文丢失恢复保证。

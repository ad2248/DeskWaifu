# 图像识别与剪贴板朗读

## 范围与基线

本文依据主线 `0058b7e` 的 `perception`、`reading_clip` 实现、测试及模块说明整理当前维护契约。“应”是可验证要求，“现状/限制”用于说明能力边界，不引入新功能或推测需求历史。本次仅核对源码，未执行测试、真实模型推理或真实桌面截图。

### 目标

- 提供异步本地图片 OCR，明确初始化、任务和错误状态，避免模型推理阻塞主程序。
- 显式触发时读取剪贴板图片，按图片准备 → OCR → 语音顺序朗读，并能取消、恢复至空闲。
- 保留独立 Portal 截图服务，正确处理授权交互、取消和解码；不把独立截图能力误写成已接入朗读流程。

### 非目标

不监听剪贴板变化自动朗读，不朗读剪贴板纯文本，不连续看屏或静默抓屏；不提供截图选区 UI、截图到 OCR 自动串接、任意 ONNX 模型兼容、模型自动下载/转换、排版还原或 OCR 沙箱。本文不承诺真实桌面准确率、逐字节一致性或实时性能。

## 可验证需求

| ID | 要求与当前实现边界 | 验收入口 |
| --- | --- | --- |
| IM-01 | `image.read/v1` 应读取一次图片快照；剪贴板访问在 GUI 线程，PNG 编码在后台。空图片、单边超过 4096 或编码失败应失败；忙时拒绝，不排队。内部调用可显式提供 `QImage`，不等于对外任意格式上传接口。 | `ImageProcessor.cpp`、`ImageFile.cpp`、适配器测试 |
| IM-02 | 临时 PNG 应由共享生命周期持有，在排队及 OCR 使用期间有效，最终引用释放后清理；取消编码不应继续推进朗读。停止 OCR 时应先终止/等待借用文件的 helper，再释放文件。 | `ImageFile.hpp`、`OcrProcessor.cpp`、流水线测试 |
| IM-03 | OCR 应通过独立 CPU helper 完成，应用侧仅使用 Qt 客户端。生产配置应启动异步模型检查，以 `availability_state=checking/available/unavailable` 区分可用性；完成模型加载和试运行后才可 ready。检查中拒绝新识别且不创建任务。 | `OcrClient.cpp`、`OcrEngine.cpp`、客户端及原生模型测试 |
| IM-04 | 应提供 `get_ocr_status`、`ocr_recognize`、`get_ocr_result`、`cancel_ocr` 命令能力。识别接受绝对、可读本地文件路径，接受后返回 `job_id`，而非同步返回推理结果。忙时拒绝，只保留最近任务；取消仅作用于匹配的待处理任务。 | `PerceptionPlugin.cpp`、`OcrProcessor.cpp`、`OcrClientTest.cpp` |
| IM-05 | OCR 模型配置应从 `<configRoot>/plugin/perception/config.json` 读取两个目录项；缺省使用系统路径，显式空值、非字符串、含 NUL 或非绝对目录应失败，不展开 `~`/环境变量、不静默回退。初次加载失败后不后台重试；曾成功初始化的 helper 在超时/协议故障/崩溃后可由下一用户请求重启。 | `ConfigureModels/Submit`、客户端测试 |
| IM-06 | 原生识别应限制单帧、单边不超过 4096、文件不超过 64 MiB，请求行不超过 64 KiB；结果包含原图尺寸、文字行、置信度、四点像素坐标及耗时。客户端应检查协议版本、任务 ID、尺寸、有限数值、置信度及坐标范围，并限制回复缓冲为 4 MiB。 | 原生引擎、`native/main.cpp`、客户端及原生测试 |
| RC-01 | `reading_clip` 命令应立即返回 `ok=true,queued=true`，表示触发已入队，不等于朗读成功。空闲时请求 `image.read/v1` → `ocr.recognize/v1` → `speech.speak/v1`；按 helper 返回行顺序用换行连接文字，识别为空则失败且不播报。 | `ReadingClipProcessor.cpp`、流水线与动态插件测试 |
| RC-02 | `get_reading_clip_status` 应返回 `ok/state/error`；状态序列为 `idle → reading_image → recognizing → speaking → idle`，变化通知 `reading.state/v1`。任一步失败、缺失能力或无效回复都应以错误回到 idle，不能假报成功或启动下一步。 | 流水线、动态插件与跨插件契约测试 |
| RC-03 | 非空闲时再次触发应取消当前步骤并进入 `cancelling`，取消中重复触发不启动新流程；迟到完成不得恢复旧流程。停止插件应取消在途请求并释放自身资源。动态能力路径每步超时为 65000 ms。 | `ReadingClipProcessor.cpp`、取消/停止测试 |
| SS-01 | 截图只应在显式 `Capture` 时调用 XDG Desktop Portal，传 `interactive=true`；忙时返回空 ID，不排队/替换。正常存活的已接受请求应异步以一次成功或失败结束，取消只匹配当前 ID。 | 截图接口、Portal 实现、模拟 Portal 测试 |
| SS-02 | 截图应只解码无 host 的本地 `file:` URI，不改写/删除 Portal 文件；后台拒绝动画、无效图片、超过 64 MiB、单边超过 16384 或超过 32 Mi 总像素的图片。完整请求默认 60 秒超时，取消/析构尽力关闭 Portal 请求，不回退绕过授权。 | Portal 实现及截图测试 |

## 现行设计与维护入口

- 插件组装：[PerceptionPlugin.cpp](../../src/plugins/perception/PerceptionPlugin.cpp) 注册 OCR 命令并创建图片、OCR、截图适配器；[ReadingPlugin.cpp](../../src/plugins/reading_clip/ReadingPlugin.cpp) 只提供朗读命令和状态命令，依赖能力总线而非宿主硬编码业务顺序。
- 图片与生命周期：[ImageProcessor.cpp](../../src/plugins/perception/private/processor/image/ImageProcessor.cpp)、[ImageFile.cpp](../../src/plugins/perception/private/processor/image/ImageFile.cpp)、[共享 ImageFile.hpp](../../sdk/contracts/ImageFile.hpp)。图片位于 `QTemporaryDir` 下的 `image.png`。取消编码是标记取消并等待后台完成，并非中断编码线程；服务停止会等待后台任务。
- OCR 适配：[OcrProcessor.cpp](../../src/plugins/perception/private/processor/ocr/OcrProcessor.cpp) 持有临时图，按行组合识别文本；取消/错误时可能将图片保留至 `WorkerStopped`，避免 helper 尚在读取时删除。[OcrClient.cpp](../../src/plugins/perception/private/processor/ocr/OcrClient.cpp) 用 `QProcess` 参数列表启动 helper，不经 shell 拼接，stdin/stdout 逐行 JSON，无额外网络监听。默认初始化/请求超时与空闲退出分别为 60 秒。
- 推理与部署：[原生 OCR README](../../src/plugins/perception/native/README.md)、[OcrEngine.cpp](../../src/plugins/perception/native/OcrEngine.cpp)、[main.cpp](../../src/plugins/perception/native/main.cpp)。仅支持官方 `PP-OCRv6_small_det` 与 `PP-OCRv6_small_rec` ONNX 及配套 `inference.yml`，字典来自 YAML。默认目录为 `/usr/share/deskwaifu/ocr/models/PP-OCRv6_small_det` 和 `/usr/share/deskwaifu/ocr/models/PP-OCRv6_small_rec`；配置键为 `ocr_detection_model_dir`、`ocr_recognition_model_dir`。构建安装 helper 不要求已有模型；模型显式单独部署。
- 朗读状态机：[ReadingClipProcessor.cpp](../../src/plugins/reading_clip/private/processor/reading_clip/ReadingClipProcessor.cpp)。业务完成取决于语音终态，不是 OCR 已返回；语音边界见 [语音与凭据](语音与凭据.md)。
- 独立截图：[截图 README](../../src/plugins/perception/private/processor/screenshot/README.md)、[IScreenshotService.hpp](../../src/plugins/perception/private/processor/screenshot/IScreenshotService.hpp)、[PortalScreenshotService.cpp](../../src/plugins/perception/private/processor/screenshot/portal/PortalScreenshotService.cpp)。Busy 包含取消后尚未释放的解码任务；销毁不再发结果，晚到句柄仍尽力关闭。截图像素不承诺桌面逻辑坐标或多屏/DPI 映射。

## 失败安全与隐私边界

- OCR 图片与模型在本机处理，不自动下载模型、不上传图片、不保存识别结果到磁盘；但客户端会在内存保留最近任务结果供查询，剪贴板朗读会把识别出的文字交给云端语音服务。不能宣称完整朗读链路完全离线。
- 临时 PNG 在磁盘存在至共享引用释放。正常资源清理不等于崩溃后的安全擦除保证；外部提交的原图和 Portal 文件不由本模块删除。
- helper 以本用户权限读取授权路径，模型/图片解析不是安全沙箱。`DESKWAIFU_OCR_HELPER` 是开发覆盖可执行路径的入口，不是运行任意 shell 命令的接口，部署者仍需信任该程序与模型来源。
- 客户端丢弃 helper stderr，不把图像内容写入应用日志；OCR 错误状态仍可能含本地路径和模型加载说明，不能按“凭据级脱敏”理解。语音错误/凭据另见语音文档。
- 模型不可用应停用 OCR 而不阻止其他能力。取消会终止 helper 并等待其退出，已验证的 OCR 不因取消永久停用；旧进程停止期间新请求仍可能被拒绝。
- Portal 不可用应明确失败，不自动重试、不绕过 Portal。真实截图范围和授权窗口由桌面后端决定，不能承诺所有桌面都有相同选区体验。

## 已知限制与待确认

- 截图服务虽然由感知插件创建，但当前未提供外部截图命令或截图 UI，也未接入 `reading_clip`；朗读输入是剪贴板图片。
- 原生检测缩放策略及浮点多边形扩张与 PaddleX 参考实现不完全相同；合成图比较采用 NFKC 并忽略空白，不承诺全角标点逐字节一致。字符行顺序也不等于复杂文档排版还原。
- [历史 RESULTS.md](../../src/plugins/perception/native/RESULTS.md) 使用旧模型组合，仅作历史材料，不得作为当前 small+small 模型准确率/性能结论。
- 模型配置变化或首次加载失败修复后需重启；可恢复进程故障的按需重启不是模型自动修复或后台轮询。
- 真实桌面 Portal 授权、不同图片格式插件、模型部署和云端语音/设备组合须在目标环境另行验收。源码存在测试入口或测试被跳过都不能视为真实环境已通过。

# 模块职责（#77）

> 基线：`0058b7e`。本文区分规范要求、现行设计与证据边界：约束性措辞保留原文要求；现行行为和限制不自动升级为规范；测试描述不代表本次迁移已执行验证。插件所有权以[插件架构](插件架构.md)为权威。

`src/plugins/desktop/private/app/LAppDelegate` 只是 desktop 的组装/生命周期根。InteractionProcessor 拥有窗口/输出/配置状态，其后端为 QtDesktopWindow。当前事件图见[插件所有权](插件架构.md)。以下展示 desktop 的组装与模型执行路径，是组装/调用关系，不是完整的构建依赖图或所有权图。

```text
desktop/Delegate（仅接线和生命周期）
  ├── InteractionProcessor → deskwaifu_input（指针到模型的变换和点击策略）
  ├── InputListener + SignalProcessor
  └── ModelProcessor → model-render 线程 → ModelRuntime
        ├── View → LAppLive2DManager（活动模型、命中处理）
        ├── 纹理存储
        └── LAppLive2DManager
              ├── deskwaifu_catalog（稳定路径 ID、确定性排序）
              ├── deskwaifu_loader → 目录描述符、模型/资源存储
              ├── ModelSession → ModelCache（所有者、预取和淘汰）
              └── deskwaifu_renderer（单个 GL 帧、投影、前置/后置钩子）
                    → 借用的活动模型（通常由 session 所有）
```

ModelRuntime 在 model-render 线程创建 View、manager 和纹理存储；模型加载、更新、GL 绘制与拆除也在该线程执行。Manager 调用 renderer；ModelSession 和 ModelCache 不依赖 renderer。

目录和输入辅助对象仍为 desktop 内部实现。它们使用共享插件 SDK，但不直接链接 GL 或 Wayland。独立 IPC 插件不依赖 desktop；CommandProcessor 仅通过公开的 `command.<name>/v1` 能力路由，对缺失或有歧义的提供者返回明确错误。传输层和其本地适配器都包含小型契约 `ICommandService.hpp`；传输层不包含具体处理器头文件。Renderer 和 loader 依赖 Cubism。Manager 将缓存的模型指针保持为私有，由 `ModelSession` 拥有；View 只在一帧期间借用活动指针。启用 `USE_RENDER_TARGET` 或 `USE_MODEL_RENDER_TARGET` 时，manager 还拥有一个 session 之外的额外示例模型，并将其纳入绘制。

选择失败时保持原模型活动；预取失败不致命。选择会同步预取下一个索引；目录超过四项时，常规淘汰只保留当前和下一个模型。默认 128 MiB 纹理软预算可以淘汰其他缓存模型，包括预取模型，但始终保留活动模型。共享纹理按每个模型分别计入该预算；它不是 GPU 显存硬上限。

可见名称重复的模型具有不同的“规范目录 + 文件名”ID（JSON 文件可以符号链接到共享资源，但不会合并模型会话）。现行按名称进行的 IPC 查找选择排序后的最后一个匹配项，因为每次名称匹配都会覆盖所选索引。启动时的 `defaultModel` 查找则选择排序后的第一个匹配项。这是现状差异，不在本文中规范化为统一选择规则。

`BUILD_TESTING=ON` 会构建并注册已启用插件的目录、缓存、会话、输入、依赖方向及 IPC 传输测试，即使 `DESKWAIFU_BUILD_CONTROL=OFF` 也如此；由 CTest 执行。Qt 模型窗口及其常规测试仍启用，但完整的 `qt-desktop-window` 和 `gpu-transfer` 集成测试还要求 `DESKWAIFU_QT_LIVE_TEST=ON`。禁用控制应用还会排除 launcher/respawner、Qt client/panel、model-hotkeys、model-transform 和 model-keyboard 测试。语音契约和组件测试独立于 CONTROL，但要求 `DESKWAIFU_BUILD_SPEECH_PLUGIN=ON`。`DESKWAIFU_TEST_GATE=ON` 要求启用 BUILD_TESTING、CONTROL 以及全部五个后端插件构建选项。

配置校验、变换/可见性修改以及持久/流式外部控制属于 GUI interaction 所有者。模型状态/操作属于 ModelProcessor；平台相关的输出选择是 GUI 所有者的内部实现。

语音凭据和读取编排属于后端插件，不属于 GUI interaction 所有者。控制进程加载可选 GUI 插件入口，这些页面使用 IPC，不使用后端对象。仅 GUI 的 system/interaction/model 模块提供页面；模型/窗口/输入后端业务由 desktop 所有，不属于这些 GUI 模块或平台。参见[GUI插件所有权](GUI插件.md)。

## 需求验收与证据边界

- 核对模块职责、模型线程执行与借用期限，以及加载失败、预取和软预算的既有行为。
- 将同名模型的 IPC/启动选择差异记录为现状限制，不把两者任一选择方式新增为统一规范。
- 按实际构建选项核对测试注册范围，不把关闭 CONTROL 或未开启实时测试时的结果当作全部集成测试证据。

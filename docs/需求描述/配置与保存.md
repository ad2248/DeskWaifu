# 配置与保存

> 核对基线：`0058b7e`。保存语义以 `ConfigStore`、`LAppConfig`、`TransformEditor` 及设置类为依据；本页不承诺所有插件共享同一事务。

## 目标与配置边界

用户可从 JSON 配置恢复桌宠行为，并在 GUI/IPC 修改设置时得到明确成功、失败和冲突反馈。主配置默认 `$XDG_CONFIG_HOME/deskwaifu/config.json`，未设置时为 `~/.config/deskwaifu/config.json`；`--config` 覆盖路径。插件配置根位于该文件路径父目录的 `plugin/<name>/`，不追踪主配置符号链接来改变插件根。

宿主只解释 `plugin_dir`；桌面字段由 desktop 管理，语音和 perception 的配置语义由各自插件决定。[SDK JSON 辅助工具](../../sdk/README.md)的 `QSaveFile` 写入不是 `ConfigStore` 的并发编辑事务，不能混为一谈。

## 字段与默认值

- 模型：`additional_model_dirs=[]`、`default_model=""`。
- 变换：`model_scale=1`、`model_x=0`、`model_y=0`，`window_width=1900`、`window_height=1000`；`model_region` 缺省不裁剪。
- 交互：`emotion_timeout=5`、`hover_opacity_enabled=false`、`hover_opacity=0.5`、`idle_opacity=1`、`mouse_look_radius=0.5`。
- `model_output` 未指定时使用第一个枚举输出；`render_device` 空值/未指定在当前实现中表示自动，用户接口使用 `auto`。
- `plugin_dir` 缺省为安装前缀下的插件目录（遵循 GNUInstallDirs），空字符串禁用发现；后端和 GUI 环境覆盖分别见[插件架构](插件架构.md)和[GUI 插件](GUI插件.md)。

字段行为及有效范围分别见[模型交互与显示](模型交互与显示.md)、[语音与凭据](语音与凭据.md)、[图像识别与剪贴板朗读](图像识别与剪贴板朗读.md)。根 README 保留可直接使用的示例，不维护第二份保存协议。

## 需求与验收

- **CFG-01 解析**：主配置可含行注释；重复键、损坏 JSON 和被当前 Decode 明确拒绝的业务字段不能被保存操作静默覆盖。旧数值字段的宽松解析是例外：部分无法转换的值会默认化，后续全量保存可能写入默认值，见下文现状限制。文件不存在可按默认值运行并在保存时创建。IPC 请求不允许注释。
- **CFG-02 写入所有权**：GUI 通过命令请求后端写配置，不直接改后端私有文件；所有桌面设置写入后端实际的主配置路径，包括自定义 `--config`。
- **CFG-03 全量序列化**：桌面保存从当前值结构重新生成整个配置，包含已知默认值并保留未知 JSON 字段值，不保留注释、原格式或内部运行元数据。不能因保存透明度等设置丢失独立已知字段。
- **CFG-04 原子替换**：先校验再写临时文件并原子提交，保留已有文件权限和符号链接指向，不留下部分 JSON。失败返回错误；设置类中要求保存成功才更新的值不得提前提交运行状态。不能把原子 rename 外推为断电耐久性保证。
- **CFG-05 编辑独占**：位置/缩放/裁剪只有一个连接可持有事务；预览不改持久文件。其他连接不能更新、提交或取消它；所属连接断开取消。屏幕编辑属于本地所有者，和面板编辑共享事务。
- **CFG-06 冲突**：编辑开始保留比较快照，应用前比较完整配置。外部修改或独立设置保存不能被静默覆盖；用户显式选择全量覆盖或丢弃并重读。外部变化不替换当前草稿。
- **CFG-07 保存失败恢复**：应用失败保留草稿和编辑框，显示原因可重试；Reset 只有保存成功才结束事务。编辑外滚轮变换在空闲后自动保存，失败保留未保存状态并提供重试，不声称已落盘。
- **CFG-08 热加载**：在正常呈现驱动的轮询中约每 0.5 秒检测文件替换；变换/裁剪与透明度支持刷新。透明度、注视半径查询会刷新磁盘状态。不能据此承诺全部字段热更新；渲染设备和插件等需重启。
- **CFG-09 GUI 反馈**：透明度独立于变换事务，滑条释放、键盘/滚轮调整应用并保存；保存失败恢复后端有效值。断线/旧后端禁用不支持控件，重连查询状态，不自动重放结果未知的写入。
- **CFG-10 丢失响应**：变换保存请求使用 ID，可查询近期结果；结果不跨后端重启保留。独立设置命令丢失确认后先查询，不能把重试当作通用安全策略。

## 现行实现与限制

- [配置值与序列化](../../plugins/desktop/private/processor/interaction/config/LAppConfig.cpp)、[编辑事务](../../plugins/desktop/private/processor/interaction/TransformEditor.hpp)、[存储实现](../../sdk/contracts/ConfigStore.cpp)是核对来源。
- 旧数值字段的 Decode 路径对部分无法转换值保留默认，编辑器另做更严格的有限值及缩放校验。此差异只记录现状，不承诺“所有字段严格同构校验”；后续统一应另立变更。
- 外部编辑器不遵守应用协议；rename 前的内容比较只能缩小竞态窗口，不是对不合作写入者的完整 CAS。无权宣称所有并发更新都不会丢失。
- 未知值被保留也意味着旧 `minimax_api_key` 可能仍在文件中；不会自动导入语音插件或自动删除，应由用户迁移后手动移除。凭据权限与不回显要求见语音专题。

# 语音输入使用说明

语音输入由独立的 `voice_input` 插件提供，与 **语音** 页的 MiniMax TTS 无关。流程是：主动录音 → 停止 → HTTP 语音识别 → 写入系统剪贴板 → 用户自行粘贴。它不是 Fcitx/IBus 输入法，不注入 Ctrl+V，也不会向当前窗口自动输入。

## 环境与首次配置

- 构建默认启用 `DESKWAIFU_BUILD_VOICE_INPUT_PLUGIN=ON`，需要 Qt 6 Multimedia/Network/DBus、pkg-config 和 libsamplerate。
- 运行需要可用的麦克风及 Qt 音频后端；Wayland 后台复制需要 `wl-clipboard` 的 `wl-copy` 和合成器支持的剪贴板协议。缺少依赖或协议不支持时会报错，不会抢焦点或静默换用其他后端。
- 控制面板与主程序必须发现同一个插件目录。开发运行时可设置 `DESKWAIFU_CONTROL_PLUGIN_DIR=/绝对路径/build/plugins`。
- 在控制面板 **语音输入** 页填写完整 HTTPS ASR 端点、模型与 API key，选择设备并保存。未指定设备时，每次开始使用当时的默认输入设备；指定设备不可用时直接失败，不静默换麦。

参考端点为：

```text
https://llm-y3exskfcgxgxzn23.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
```

默认模型为 `qwen-audio-3.0-asr-flash`。这是业务空间的专用地址，不保证所有 DashScope 账户可用；请按自己的服务权限修改并验证。对于兼容模式模型，以 `/v1` 结尾的基础端点自动追加 `/chat/completions`，已填完整路径时不重复追加，使用 `messages` 中的 `input_audio` Data URI、`stream:false`，读取 `choices[0].message.content`。**默认模型 `qwen-audio-3.0-asr-flash` 只支持原生 ASR 协议**：填写上述兼容基础地址时，发送前确定性解析为同一域名下的 `/api/v1/services/aigc/multimodal-generation/generation`，不在失败后重试，也不改变凭据接收主机。该规则已通过真实请求核验，不将 GET 模型列表成功当作音频协议可用的证明。仍兼容原项目的原生完整 `/api/v1/services/aigc/multimodal-generation/generation` 端点（`input.messages` 与 `text/output.text` 协议）。两者都使用 Bearer key、16 kHz 单声道 PCM16 WAV/base64，不是 multipart `/audio/transcriptions` 或 WebSocket 接口，也不自动适配任意 ASR 服务。

配置保存在主配置目录下 `plugin/voice_input/`，与 TTS 配置分离。凭据文件权限为 `0600`，但内容仍是明文，不是加密密钥库；不要分享、提交或备份到不可信位置。查询设置不会返回 key 原文。建议通过 GUI 输入 key，避免 shell 历史和进程参数暴露秘密。

## 录音与控制

在控制面板开始录音，再次停止后识别；也可使用 CLI：

```bash
deskwaifu-ctl start_voice_input
# 将 1 替换为开始录音或状态查询返回的 session_id
deskwaifu-ctl stop_voice_input --session_id 1
deskwaifu-ctl toggle_voice_input
deskwaifu-ctl cancel_voice_input --session_id 1
deskwaifu-ctl get_voice_input_status
deskwaifu-ctl get_voice_input_result --session_id 1
deskwaifu-ctl retry_voice_input_copy --session_id 1
deskwaifu-ctl list_voice_input_devices
deskwaifu-ctl get_voice_input_settings
deskwaifu-ctl set_voice_input_settings --max_recording_seconds 60
```

`toggle_voice_input` 在空闲时开始，在录音时停止并识别。识别或其他收尾任务进行中再次 toggle 返回 busy，不会隐式取消或排队。取消使用独立命令；取消后的旧识别结果不得触发新的复制，但已经完成的系统剪贴板写入不能撤销。

最长录音默认 60 秒，可设为 1–300 秒；到时自动停止并识别。设置变更只影响下一次会话，不修改正在录制或识别的配置快照。状态查询不返回完整识别文本；只有显式结果查询取得文本。识别成功不等于复制成功，只有剪贴板后端确认完成才应显示“已复制”；失败或结果未知时请查看状态，不要假定剪贴板已经更新。面板“重新复制”及 `retry_voice_input_copy` 只传会话号，由后端复制保留的文本，不会因长结果超出 IPC 请求帧上限而断线。

## 合成器快捷键

快捷键由合成器配置，不由桌宠抢占键盘焦点。例如 Sway：

```text
bindsym $mod+v exec deskwaifu-ctl toggle_voice_input
```

Hyprland 示例：

```text
bind = SUPER, V, exec, deskwaifu-ctl toggle_voice_input
```

这些只是示例，请避免与已有快捷键冲突。若合成器环境找不到 CLI，使用安装后的绝对路径；命令与桌宠需要同一用户和正确的 `XDG_RUNTIME_DIR`。成功后在目标应用中自行粘贴，不需要先点击桌宠。

## 隐私与故障排查

- 初始化和插件加载不自动打开麦克风或上传音频；用户开始后，停止录音或达到时限会把整段音频上传到所配置服务。云端处理、保留策略及费用由服务商决定。
- 默认不把原始录音和识别文字写入文件，不在普通日志或系统通知展示全文。显式结果查询、系统剪贴板及剪贴板管理器仍可能保留敏感文字；不要将这些输出当作无敏感信息的诊断材料分享。
- **缺凭据/端点错误**：检查语音输入页，而不是 TTS 页。确认 HTTPS 地址、模型和账户权限；网络错误不会自动重试上传。
- **设备不可用/录音失败**：检查系统录音权限、默认输入设备和已保存设备 ID。设备拔出后应结束本次会话并报告错误。
- **busy**：等待当前识别或清理完成，或显式取消；不要反复触发并期待排队。
- **识别为空**：空或仅空白结果按未检测到语音处理，不用空文本清空剪贴板。
- **复制失败/结果未知**：检查 `wl-copy` 可执行文件和当前 Wayland 会话的协议支持。不应以 offscreen 单测成功代替无焦点桌面复制验证。

## 测试边界

普通门禁要求 `voice-input-audio`、`voice-input-asr`、`voice-input-settings`、`voice-input-state`、`voice-input-controller`、`voice-input-gui`、`voice-input-plugin-load` 及 `clipboard-service`，另由 backend-capabilities 通过真实 socket 验证配置接线。测试使用本地 fake/离线数据，不访问真实麦克风、系统剪贴板或云端，不需要 API key。完整门禁不允许关闭 voice_input 缩减覆盖。

真实录音、后台 Wayland 复制和云端识别属于单独授权的验收；普通测试通过不能证明设备、合成器或云端账户可用。请勿在未确认隐私和计费影响时进行 live 测试。

显式云端入口（使用生产 ASR 客户端和仓库中的合成语音，不访问麦克风/剪贴板）：

```bash
# 通过安全方式在测试进程环境中设置，不把实际 key 写进命令历史。
export BAILIAN_OPENAI_ENDPOINT='https://llm-y3exskfcgxgxzn23.cn-beijing.maas.aliyuncs.com/compatible-mode/v1'
# BAILIAN_API_KEY 由调用方注入；缺少任何一项都会失败。
build/bin/voice-input-live-test plugins/voice_input/tests/fixtures/voice-input.pcm
```

CI 的独立 live 步骤读取仓库密钥 `BAILIAN_API_KEY` 和仓库变量 `BAILIAN_OPENAI_ENDPOINT`，不向外部 PR 暴露凭据。两项都未配置时明确报告禁用；只配置一项时失败，不伪装测试通过。云端测试不加入普通 CTest，不输出 key 或完整转录，仅校验合成短句的已知词语。

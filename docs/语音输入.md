# 语音输入使用说明

`voice_input` 是 DeskWaifu 的 Rust 动态插件，使用独立于 TTS 的配置。快捷键启动定时录音，录满后插件将音频发送到配置的识别服务。识别成功后，插件写入 Wayland 剪贴板，由用户在目标应用中粘贴。

## 配置麦克风和识别服务

首版面向 Linux Wayland。录音由 PipeWire 提供，使用会话的默认麦克风，可用 WirePlumber 管理默认设备。剪贴板依赖 `wl-clipboard` 和合成器的后台剪贴板协议。Arch 包安装插件和运行依赖。开发时可运行 `bash scripts/build.sh` 将插件放到宿主旁边。

配置文件位于 `$XDG_CONFIG_HOME/deskwaifu/voice_input.json`。未设置绝对的 `XDG_CONFIG_HOME` 时使用 `~/.config/deskwaifu/voice_input.json`。用 `chmod 600` 设置文件权限，在编辑器中填写真实 API key。

```json
{
  "endpoint": "wss://llm-y3exskfcgxgxzn23.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference",
  "model": "qwen-audio-3.1-asr-flash-streaming",
  "max_recording_seconds": 60,
  "api_key": ""
}
```

示例 WSS 地址属于特定业务空间。请使用账户有权访问的端点和模型。录音时长默认 60 秒，范围为 1–300 秒。修订配置后，下一次录音使用新的配置，进行中的会话继续使用原来读取的设置。`get_voice_input_settings` 返回密钥是否已配置。

迁移旧版时，将语音输入配置中的 ASR 端点、模型、密钥和录音时限复制到上述字段。旧版兼容模式 HTTPS 端点的 `/v1` 会补全为 `/chat/completions`。若模型为 `qwen-audio-3.0-asr-flash`，兼容路径会在上传前解析为同域的原生 API 路径。Rust 版本目前使用定时录音，控制面板、手动选择设备和提前停止属于后续入口。

## 启动和查询会话

先启动 `deskwaifu`，再使用 `deskwaifucli`。

```bash
deskwaifucli start_voice_input
deskwaifucli get_voice_input_status
deskwaifucli get_voice_input_result --session_id ID
deskwaifucli retry_voice_input_copy --session_id ID
deskwaifucli get_voice_input_settings
```

将 `ID` 替换为启动或状态返回的字符串 `session_id`。录音、识别或复制进行期间，再次启动会收到 `busy`。WSS 在录音结束后按每 100 ms 一块发送 PCM，因此上传大约需要再等一遍录音时长。

状态返回阶段、时长、错误码和复制结果。通过显式结果查询可读取转录。超出 IPC 帧限制时返回 `result_too_large_for_ipc`，完整文本仍可通过会话 ID 重试复制。复制失败或结果未知时可显式重试。空白转录返回 `no_speech`，并保留原来的剪贴板内容。

## 绑定快捷键

例如在 Sway 的配置中添加：

```text
bindsym $mod+v exec deskwaifucli start_voice_input
```

在 Hyprland 中使用：

```text
bind = SUPER, V, exec, deskwaifucli start_voice_input
```

在具有默认麦克风的 Wayland 会话中运行宿主。识别并复制完成后，在需要输入文本的应用中手动粘贴。

## 排查问题

- `not_configured` 或配置错误时，检查文件路径、`0600` 权限、API key 和账户的模型权限。
- 录音错误时，检查 PipeWire 会话和默认麦克风。录音失败时该会话会跳过云端识别。
- 复制失败时，检查 `wl-copy` 是否可用以及宿主进程是否继承了 Wayland 会话环境。可用 `wl-paste --no-newline` 读回文本。
- 录音和转录保存在内存中。转录可经显式查询和剪贴板传出，剪贴板管理器可能保存历史。云端数据处理和计费由配置的服务商决定。

## 验收范围

普通测试以环回 mock 验证 WSS 事件、PCM 分块和尾静音，并覆盖两种旧版 HTTPS 请求。隔离的 PipeWire 与 headless Sway 验证了定时录音、设备断开、剪贴板读回和复制重试。端到端测试副本使用本地 HTTP mock，发布构建要求 WSS 或 HTTPS。Sway 1.10.1 与 wl-clipboard 2.2.1 已验证后台剪贴板读写。实际百炼账户及物理麦克风需要在目标环境另行验收。

description: 修复 PR 审查中的阻塞问题并回复验证结果
---

响应以下 PR 审查中提出的阻塞性问题：
$ARGUMENTS

接受 PR URL，或当前上下文已明确关联的唯一 PR。目标缺失或有歧义时先询问，不猜测仓库或 PR 编号。

1. 读取仓库的 AGENTS.md、存在的 tea.md 和提交规范。通过 session.link 关联目标 PR；仅关联用户提供或上下文已明确的相关工单，不搜索或推断潜在关联。
2. 使用 tea 读取 PR 最新 head/base、全部评审与行内评论、讨论及当前提交的 CI 状态。区分阻塞问题、非阻塞建议和已失效意见，逐项核对最新代码，不只依赖评审摘要。
3. 检查 git status、远端、分支和最近提交，fetch 后确认工作区对应 PR 的源分支。不得直接在 main 上修改；需要隔离时通过 session.moveToWorktree 切换到该 PR 分支的工作树。保留用户或其他 agent 的改动，不重置、丢弃、强推或夹带无关修改。
4. 将确认成立的阻塞问题转为简短修复与验证清单。缺陷尽可能先添加失败的回归测试，再做最小修复；不顺手实现非阻塞建议或扩大需求。意见不成立或需求有歧义时，给出代码与验证证据，必要时向用户询问，不盲目修改。
5. 若目标分支冲突阻塞本次交付，先检查冲突双方意图，再合并 PR 的目标分支并逐项解决；保留双方仍有效的行为，补充组合场景测试。不要用整文件选 ours/theirs 或重写历史来掩盖冲突。
6. 先运行相关测试，再尽可能运行完整构建和测试；检查最终 diff 与 git diff --check。未执行或失败的检查如实说明，不声称通过。
7. 遵循 submit-code-and-pr skill 的验证、提交与推送要求，但更新现有 PR，不创建重复 PR。只提交本次获授权的改动，使用中文约定式提交，正常推送 PR 源分支，不 amend、不跳过钩子、不强推。
8. 在原 PR 中逐项回复阻塞意见，包含对应评审或评论、修复或不修改的理由、验证命令与结果、提交 hash 和已知限制。必要时同步回复明确关联的工单；未解决时说明阻塞与所需输入，不宣称完成。所有修改服务端状态的 tea 命令显式传入 --login 和 --repo，评论使用真实换行。
9. 复查远端 PR 的最新 head、评审回复、CI 状态及本地工作区，向用户报告结果与 PR URL。CI 尚未完成时明确说明；请求重新审查，不擅自批准自己的改动、撤销他人评审、合并 PR 或关闭工单。

description: 创建并切换到新的工作树，处理缺陷修复或功能开发任务
---

在新的独立工作树中处理以下任务：
$ARGUMENTS

1. 若未提供任务描述，先询问要处理的任务，不创建工作树。
2. 检查当前仓库与工作区状态。若存在不属于本任务的未提交改动，先说明迁移会携带全部未提交改动并询问是否继续；未经同意不夹带、丢弃或重置它们。
3. 根据任务描述生成简短的英文短横线工作树名及专用分支名，修复使用 `fix/`，功能使用 `feat/`，其他任务使用合适的前缀。名称冲突时选用新名称，不覆盖已有工作树或分支。
4. 使用 openchamber 工具的 `session.moveToWorktree`，传入 `worktree` 和 `branch`，创建工作树并将当前会话切换过去。默认基于仓库默认分支；用户明确指定基线时传入 `startRef`。本命令已明确要求创建工作树，无需再次询问是否创建。
5. 若工具不可用或迁移失败，停止并报告原因；不得在原工作区继续修改，也不要仅在 shell 中切换目录冒充会话迁移成功。
6. 确认会话已位于返回的新目录，核对分支与工作区状态，阅读新工作树适用的 `AGENTS.md`，向用户简要报告工作树路径、分支和后续计划。
7. 在新工作树中继续完成任务：先明确验收标准，阅读相关实现，做最小改动并验证。缺陷修复应补充回归测试；需求存在实质歧义时先询问。遵守当前 agent 与权限限制，Plan 模式下只分析和规划，不实施修改。

不要仅因创建了工作树就停止；应继续处理用户提供的任务。除非用户明确要求，或任务已触发明确包含交付操作的 skill，否则不自动提交、推送或创建 PR。

---
description: 每两分钟监控最新 PR 的 CI，失败则分析并修复，成功后停止且不合并
agent: build
subagent: false
---

监控当前仓库最新 PR 的 CI，直到当前 PR 的必需 CI 全部成功；成功后立即结束任务，绝不合并 PR。以下为可选的补充要求：
$ARGUMENTS

1. 先阅读适用的 `AGENTS.md`、存在的 `tea.md` 和仓库提交规范，检查工作区、当前分支、远端及 PR 关联关系。优先使用当前会话已经明确关联的 PR；否则通过当前分支在远端查找最新的、未关闭的 PR。若无法唯一确定目标 PR，先询问用户，不猜测仓库、PR 编号或分支。
2. 使用 `session.link` 关联目标 PR。使用 `tea` 查询 PR 最新 head SHA、base 分支、源分支、必需检查和全部 CI 状态；所有服务端状态修改命令显式传入 `--login` 和 `--repo`。只认当前 PR 最新 head SHA 的检查结果，旧提交的成功或失败均无效。
3. 以 120 秒为检查间隔持续轮询最新 CI。每轮检查前重新读取 PR head SHA 和 CI 状态，避免遗漏新推送触发的检查。等待期间可使用 `sleep 120`，但不得在 CI 已完成后继续等待。
4. 若 CI 仍在运行或排队，简要记录当前状态并等待下一轮；不要重复推送、创建重复 PR、回复无关工单或修改 CI 配置来绕过检查。
5. 若 CI 失败，必须获取失败 job 的完整日志，定位最具体的失败测试、构建错误或环境原因，区分代码缺陷、测试缺陷、基础设施故障和与本 PR 无关的失败。先给出失败原因分析，再对当前 PR 分支实施最小修复；修复程序缺陷时补充回归测试。不得只重跑 CI 伪装修复，也不得忽略失败。
6. 失败原因为基础设施或外部依赖且代码无需修改时，提供日志证据并在不改变代码的前提下重新检查/重跑允许的 CI；若无法由当前会话修复，明确报告阻塞原因，不声称任务完成。失败原因属于本 PR 时，运行相关测试和尽可能完整的本地验证。
7. 修改前后都检查 `git status` 和 `git diff`，保留用户及其他 agent 的改动，不重置、覆盖、强推或夹带无关文件。仅提交本任务改动；提交使用中文约定式提交，正常推送 PR 源分支。需要提交或推送时加载并完整遵循 `submit-code-and-pr` skill，但只更新现有 PR，不创建新 PR。
8. 推送修复后从新的 head SHA 重新开始监控，旧 CI 结果不再作为完成依据。每次失败都记录：run/job、head SHA、失败位置、根因、修复、验证命令和提交 hash。
9. 当且仅当当前最新 head SHA 的所有必需 CI 检查成功时完成任务。最终报告 PR URL、最终 head SHA、CI run、期间处理的失败原因和修复提交、验证结果，并确认工作区及远端同步。明确说明“未合并 PR”；不得执行 merge、approve、关闭 PR 或关闭工单操作。

# 发布版本

仅在用户要求实际发版时执行，按以下顺序推进：

1. 加载 `release-notes`，整理上一次发布到最新远端 `main` 的中文版本更新说明。
2. **用户必须明确提供 tag**；缺失时先询问，不自行推算。将该 tag 打在当前远端 `main` 最新提交上并推送；已有 tag 必须核验，不覆盖或移动。
3. 启动 Gitea 工作流 **DeskWaifu Arch release**，使用该 tag 和更新说明构建安装包。tag 推送已触发构建时不重复启动；必要时用 `notes_only` 更新说明。默认每 60 秒检查本次 run，失败则获取日志、定位并处理，直到成功才进入下一步。源码修复需要新 tag 时向用户询问，不移动原 tag。
4. 主仓库从最新 `main` 创建专用分支，或使用已有的干净专用工作树。依据成功发布的实际安装包，更新 AUR 子仓库的 `PKGBUILD`、SHA-256 校验和及 `.SRCINFO`，验证后提交并推送 AUR 子仓库。保留既有改动，不夹带无关内容。
5. 更新主仓库的 AUR 子模块引用，加载并遵循 `submit-code-and-pr`，提交、推送并创建到 `main` 的 PR；不自动合并。

完成后报告 tag、源提交、发布/CI 链接、AUR 提交及主仓库 PR。中断恢复时先核验已有发布身份和进度，不重复发布或覆盖已有资产。

# DeskWaifu 日志设计草案

本文是尚未实现的日志方案。队列容量、超时和轮转参数为建议初值。

## 目标与组件职责

统一宿主诊断输出，以事件名定位启动、动态库加载、插件生命周期、IPC 就绪和退出阶段。诊断输出写入宿主的 `stderr`。CLI 的命令输出、错误提示和退出码保持现行契约。宿主事件循环与插件回调在同一线程运行，因此诊断写入使用专用线程。 [宿主事件循环](<../crates/os/src/host.rs>) · [CLI 入口](<../apps/deskwaifucli/src/main.rs>)

| 组件 | 拟承担的职责 |
| --- | --- |
| `apps/deskwaifu` | 在加载插件前安装 `tracing_subscriber`，读取过滤配置，管理日志写入线程和退出刷新期限。 |
| `crates/os` | 记录 IPC 就绪、协议拒绝类别、客户端注册故障及退出信号。 |
| `crates/runtime` | 记录动态加载和插件生命周期事件，以及已注册命令的执行结果和耗时。向宿主转发插件日志。 |
| `crates/sdk` | 生成动态库的日志初始化入口及转发器。插件业务代码使用 `log` 宏。 |

## 事件与数据约定

| 级别 | 事件 | 拟记录字段 |
| --- | --- | --- |
| `ERROR` | `host.failed`、`plugin.stop_failed` | `phase`、`error_kind`，可用时记录插件身份或 `errno` |
| `WARN` | `plugin.initialize_failed`、`ipc.client_registration_failed`、`logging.dropped` | 插件身份、`error_kind`、`dropped_count` |
| `INFO` | `host.starting`、`plugins.loaded`、`ipc.ready`、`host.shutdown_requested`、`host.stopped` | `version`、`plugin_count`、`socket_path`、`signal`、`result` |
| `DEBUG` | `command.completed`、`ipc.request_rejected` | 已注册的 `command`、`result`、`duration_ms` 或 `reason` |
| `TRACE` | `plugin.callback_completed` | 插件身份、`phase`、`duration_ms` |

- 记录 UTC 时间和级别。宿主结构化事件使用固定 `target`、稳定事件名和允许的字段。插件日志包含宿主登记的来源、模块（缺失时用 `log` target）和消息。
- socket 绑定、退出信号注册和插件启动全部成功后记录 `ipc.ready`。能够识别故障的组件记录阶段及类别。分别记录首个故障和清理故障，退出汇总记录结果。
- 日志字段排除原始 IPC 参数与响应正文、剪贴板文本、截图、OCR 文本、音频、凭据及插件返回的任意错误文本。未知命令归类为 `unknown_command`。插件自由文本只写排障所需的固定说明、计数和状态类别。
- 对重复的客户端注册失败按类别限频并报告合并数量。成功 tick 和内部消息回调只在 `TRACE` 下记录。

## 输出、背压与退出

默认以紧凑文本写入 `stderr`，级别为 `INFO`。同一套 `RUST_LOG` 过滤宿主和插件的日志。配置接受全局级别、`target=级别` 和 `off`，优先采用最具体的目标前缀。无效配置回退到默认过滤器并记录一次错误。宿主目标包括 `deskwaifu::host`、`deskwaifu::ipc`、`deskwaifu::runtime`。插件目标使用 `deskwaifu::plugin::<库文件名去掉 lib 前缀和 .so 后缀>::<log target>`。

```sh
RUST_LOG=info,deskwaifu::ipc=debug,deskwaifu::plugin::deskwaifu_test_plugin=debug deskwaifu
```

调用线程负责过滤、有界格式化与尝试入队。每条记录编码后上限为 4 KiB，包含行终止符。格式化时转义换行并保留有效 UTF-8。队列建议容量为 1024 条，记录正文上界约 4 MiB。队列满时丢弃新记录并累计数量，写入线程恢复后直接输出 `logging.dropped` 摘要。

宿主完成运行及资源清理后关闭入队，等待写入线程刷新，建议上限 1 秒。退出码反映宿主运行结果。期限到达后允许进程退出。日志句柄的析构须立即返回。启动日志设施失败时尽力输出固定诊断并按启动失败退出。

### 可选文件输出

按需用 `DESKWAIFU_LOG_FILE=1` 启用文件输出。默认目录为 `$XDG_STATE_HOME/deskwaifu/logs`，无绝对 XDG 路径时使用 `~/.local/state/deskwaifu/logs`。建议每个文件最多 5 MiB，保留当前文件和最多四份归档。目录与文件只允许当前用户访问。文件目的地采用有界写入，失败时 `stderr` 仍可提供诊断。

## 拟新增的动态库日志入口

独立 `.so` 可以各自拥有 `log` 的全局状态。拟由 `export_plugin!` 生成 `deskwaifu_plugin_init_logging`，在动态库侧通过 `OnceLock` 持有转发器并注册为该库的 logger。转发器带宿主分配的来源 ID，包含线程安全的 `enabled` 和 `emit` 回调。插件的本地最大等级设为 `Trace`，宿主根据过滤配置决定接收哪些记录。插件使用 workspace 统一版本的 `log`，在命令回调、`stop` 或自有线程内直接调用日志宏。 [插件导出宏](<../crates/sdk/src/lib.rs#L12>)

runtime 打开库并解析入口后，以库文件名登记日志来源。先初始化日志入口，再调用构造函数。插件创建后可以补充其稳定标识。日志初始化符号缺失或注册失败时按加载错误处理。转发接口使用宿主与插件联合构建的内部 Rust ABI。 [动态加载器](<../crates/runtime/src/dynamic.rs#L16>)

宿主在转发时完成限量格式化，队列只保留宿主拥有的记录。`emit` 直接入队。插件自有线程、实例和动态库全部清理后撤销来源登记，已在队列中的记录仍可输出。

## 实施与验收

- [ ] 接入宿主 subscriber、写入队列及退出刷新。用宿主进程测试验证库加载失败和 socket 占用的错误事件、退出码及就绪事件顺序。用 runtime 测试验证单个插件初始化失败后的清理和其余插件的可用性。
- [ ] 检查 `RUST_LOG` 过滤、配置回退、CLI 输出及字段白名单。向命令和非法请求注入标记，验证 `DEBUG` 及 `TRACE` 日志未记录正文。压满写入队列后验证容量、丢弃摘要、IPC 响应和 `SIGTERM` 退出时限。
- [ ] 联合构建并加载两个实际 `.so`，验证构造、命令、worker 和停止阶段的日志归属及按插件过滤。覆盖初始化符号缺失和卸载后队列继续输出。
- [ ] 按需实现文件输出。用临时状态目录验证开关、轮转、权限和不可写目录下的降级行为。

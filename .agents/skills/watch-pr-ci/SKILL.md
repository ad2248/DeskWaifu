# 监控 PR 的 CI

按本次调用的补充要求监控目标 PR，直到当前 PR 的必需 CI 全部成功。成功后立即结束监控。全程沿用当前会话模式与权限。Plan 模式下只做分析和规划。

1. 先阅读适用的 `AGENTS.md`、存在的 `tea.md` 和仓库提交规范，检查工作区、当前分支、远端及 PR 关联关系。优先使用本次调用或当前会话明确指定的 PR。未指定时，通过当前分支在远端查找最新的、未关闭的 PR。若无法唯一确定目标 PR，先询问用户，不猜测仓库、PR 编号或分支。
2. 记录经核验的 PR URL，每轮查询都以该 URL 确定目标。使用机器上可用的 `gt` 或 `tea` 查询 PR 最新 head SHA、base 分支、源分支、目标分支保护规则中的必需检查和全部 CI 状态。先查看所选 CLI 的帮助以确认当前版本语法；服务端操作显式指定已知的主机、仓库和必要的账号信息。只认当前 PR 最新 head SHA 的检查结果，旧提交的成功或失败均无效。
3. 以 120 秒为检查间隔持续轮询最新 CI。每轮检查前重新读取 PR head SHA 和 CI 状态，避免遗漏新推送触发的检查。等待期间可使用 `sleep 120`，但不得在 CI 已完成后继续等待。
4. 若 CI 仍在运行或排队，简要记录当前状态并等待下一轮；不要重复推送、创建重复 PR、回复无关工单或修改 CI 配置来绕过检查。
5. 若 CI 失败，获取失败 job 的完整日志，定位最具体的失败测试、构建错误或环境原因，区分代码缺陷、测试缺陷、基础设施故障和与本 PR 无关的失败。先给出失败原因分析。需要修改时，逐次执行下方的「修复前核验」，通过后才编辑文件或运行用于验证修复的本地测试。使用最小修复，修复程序缺陷时补充回归测试。
6. 失败原因为基础设施或外部依赖且代码无需修改时，提供日志证据并在不改变代码的前提下重新检查/重跑允许的 CI；若无法由当前会话修复，明确报告阻塞原因，不声称任务完成。失败原因属于本 PR 时，运行相关测试和尽可能完整的本地验证。
7. 修改前后都检查 `git status` 和 `git diff`，保留用户及其他 agent 的改动。需要提交或推送时，采用修复前已加载的 `submit-code-and-pr` 中「提交前检查」「验证」「提交并推送」的要求更新现有 PR。只提交本任务改动，使用中文约定式提交。正常推送前执行下方的「推送前核验」，之后返回当前监控循环。
8. 推送修复后从新的 head SHA 重新开始监控，旧 CI 结果不再作为完成依据。每次失败都记录：run/job、head SHA、失败位置、根因、修复、验证命令和提交 hash。
9. 当且仅当当前最新 head SHA 的所有必需 CI 检查成功时完成任务。最终报告 PR URL、最终 head SHA、CI run、期间处理的失败原因和修复提交、验证结果，并确认工作区及远端同步。明确说明“未合并 PR”；不得执行 merge、approve、关闭 PR 或关闭工单操作。

## 修复前核验

1. 重新读取 PR 状态、源仓库、源分支和当前 head SHA。PR 已关闭时停止。若 head 已偏离失败检查对应的 SHA，回到监控循环，仅处理新提交的检查结果。
2. 复用已加载的 `pr-review-response` 和 `submit-code-and-pr` 指令。尚未加载时，在切换工作树前从当前可信工作树加载并保留。采用 `pr-review-response` 的工作树核验步骤。核对 Git 远端指向 PR 的源仓库（包括 fork），fetch 源分支并核对抓取到的提交。若与失败检查的 SHA 不一致，回到监控循环。必要时用 `working_directory` 切到对应的工作树，确认当前会话、分支与上游均匹配，且本地 `HEAD` 等于失败检查对应的 SHA。只在工作区安全且可快进时更新落后的本地分支。遇到分叉、未提交改动冲突或无法核验时，停止修复并报告原因。

## 推送前核验

重新查询同一 PR 和源远端分支，确认 PR 仍开放、源仓库及分支未变，且 PR head 和远端分支尖端仍为修复前核验过的 SHA。确认本地修复提交基于该 SHA，并显式推送到已核验的源远端和分支。若远端已推进或推送遭拒，保留本地改动，报告情况并从新 head 的检查结果重新判断。不得强推。

## 回归场景

| 场景 | 预期行为 |
| --- | --- |
| 在 `feat/b` 的工作树监控源分支为 `fix/a` 的 PR | 只有切换并核验 `fix/a` 的工作树后才开始编辑 |
| 源分支正确，但本地落后于失败检查对应的 SHA | 仅在安全快进并复核 SHA 后开始编辑，否则停止修复 |
| 修复期间有人更新 PR 的源分支 | 保留本地修复，停止推送并重新检查最新 head 的 CI |

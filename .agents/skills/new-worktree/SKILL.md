# 创建并切换工作树

在新的独立工作树中处理本次调用附带的任务。

1. 若未提供任务描述，先询问要处理的任务，不创建工作树。
2. 检查 `git worktree list` 和工作区状态。默认将当前工作树全部未提交的 Git 改动复制到新工作树，无需逐项确认。记录暂存区与工作区的差异（含二进制、删除和文件模式）及所有未被 Git 忽略的未跟踪文件。嵌套 Git 工作树是独立工作区，不递归复制。明确指定迁移范围时按用户要求处理。
3. 根据任务描述生成简短的英文短横线工作树名及专用分支名，修复使用 `fix/`，功能使用 `feat/`，其他任务使用合适的前缀。名称冲突时选用新名称，不覆盖已有工作树或分支。
4. 确认基线，默认使用仓库默认分支，用户显式指定时使用指定基线。以 `git worktree list --porcelain` 的首个 `worktree` 条目确定主工作树根目录，即使当前会话已在其他工作树中。新工作树的路径必须为 `<主工作树根目录>/.agents/worktrees/<工作树名>`。若 `create_worktree` 可同时满足该路径、分支名和基线要求，使用该工具创建并切换会话。否则用 `git worktree add -b <branch> <绝对路径> <base>`，再调用 `working_directory` 切换到该绝对路径。用户显式调用本技能或已要求在新工作树中处理任务时，无需重复确认创建工作树。
5. 创建或会话切换失败时，报告原因及已经创建的工作树或分支，停止实施。调用 `working_directory` 确认会话目录与新工作树路径一致。
6. 核对会话目录、分支、基线和工作区状态，阅读新工作树适用的 `AGENTS.md`。先把暂存差异应用到新工作树的索引与工作区，再把未暂存差异仅应用到工作区，最后复制清单中的未跟踪文件，保留文件类型和模式。原工作树的文件和索引保持原状。不覆盖新基线中的同名未跟踪文件目标。逐项核验暂存和未暂存改动及未跟踪文件的内容和状态，包括已有回归测试。迁移遇到冲突、失败或无法确认齐全时，停止实施，报告受影响的路径和迁移进度。向用户简要报告工作树路径、分支和后续计划。
7. 在新工作树中继续完成任务：先明确验收标准，阅读相关实现，做最小改动并验证。缺陷修复应补充回归测试；需求存在实质歧义时先询问。遵守当前 agent 与权限限制，Plan 模式下只分析和规划，不实施修改。

不要仅因创建了工作树就停止；应继续处理用户提供的任务。除非用户明确要求，或任务已触发明确包含交付操作的 skill，否则不自动提交、推送或创建 PR。

回归场景：原工作树同时存在同一文件的暂存和未暂存改动、删除的文件和未跟踪的回归测试。切换后核验这些改动均已携带，暂存状态保留，原工作树保持原状。

# 创建并切换工作树

未提供任务描述时先询问，不创建工作树。用户显式调用本技能或要求在新工作树中处理任务时，不重复确认创建。遵守当前 agent 和权限限制；Plan 模式只做只读检查和规划。

## 确定参数

| 项目 | 规则 |
| --- | --- |
| 原工作树 | 记录当前工作树的绝对根路径；用 `git worktree list --porcelain -z` 的首个 `worktree` 条目确定主工作树根目录，不把当前工作树当作主工作树。 |
| 名称与路径 | 根据任务取简短的英文短横线名称；目标必须是 `<主工作树根目录>/.agents/worktrees/<名称>`。目录或分支冲突时换名，不覆盖；路径经过符号链接而偏离指定位置时停止。 |
| 分支 | 使用专用分支：修复用 `fix/<名称>`，功能用 `feat/<名称>`，其他任务选合适的前缀。 |
| 基线 | 优先使用用户指定的基线，否则使用仓库默认分支；无法确认默认分支时先询问。创建前解析为完整提交 ID。 |
| 迁移范围 | 默认迁移原工作树全部未提交的 Git 改动，不逐项确认；用户限定范围时只传入对应的原工作树相对路径（文件或目录，不用通配符）。忽略文件和嵌套 Git 工作树不迁移。 |

## 创建、切换并迁移

1. 用 `git status --short --untracked-files=all` 检查原工作树。记录本技能目录下 `scripts/migrate.py` 的绝对路径；使用 Python 3.9+ 在创建前获取快照指纹：
   ```sh
   "$script" snapshot "$source" -- [相对路径 ...]
   ```
   默认范围省略 `--` 及其后的参数。快照记录原分支、HEAD、所选路径的索引条目和工作区状态，包括二进制、删除、重命名两端、符号链接和文件模式。两次调用之间不要修改工作树；迁移期间暂停在两边并发编辑或执行 Git 写操作。
2. 若 `create_worktree`（OpenCode 中为 `worktree_create`）能够保证指定路径、分支和基线，优先使用；否则执行 `git worktree add -b "$branch" "$target" "$base"`。使用 `working_directory` 或 `session_move` 将会话切换到目标绝对路径；用会话默认目录运行 `git rev-parse --show-toplevel` 确认切换成功，不能用 `git -C` 代替会话切换。
3. 阅读目标工作树适用的 `AGENTS.md`，再用同一脚本及相同的范围参数执行迁移，`token` 为步骤 1 输出：
   ```sh
   "$script" move "$source" "$target" "$branch" "$base" "$token" -- [相对路径 ...]
   ```
   脚本核对目标分支、基线与干净状态，分别复制索引和工作区状态。迁移路径的基线条目必须一致；目标同名、目录冲突或不支持的 Git 状态不做猜测性合并。目标逐项核验通过且原快照复核一致后，才恢复原工作树中已迁移的跟踪路径并逐项移除对应未跟踪文件。不得用 `git reset --hard` 或 `git clean` 替代定点清理。
4. 报告目标路径、分支和迁移结果，继续在新工作树完成并验证用户任务。除非用户明确要求或已触发明确包含交付操作的技能，否则不提交、不推送、不创建 PR。

**异常处理：** 任一步失败（脚本非零退出）即停止任务实施，报告原因、已创建的工作树或分支、受影响路径和两边的状态。目标核验及原快照复核通过前不清理原工作树；若清理部分完成，不擅自回滚，也不删除已核验的目标工作树。

# 提交代码与 PR

本地使用 `git`，Gitea/Forgejo 使用机器上可用的 `gt` 或 `tea`；先阅读适用的 `AGENTS.md` 和存在的 `tea.md`。先查看所选 CLI 的帮助，确认当前版本语法；服务端操作显式指定已知的主机、仓库和必要的账号信息。

使用本次调用的补充要求交付当前任务。缺少必要信息时先询问。

准备创建 PR 时，在任何工作树切换前从当前工作树加载并保留 `watch-pr-ci` 和它用于核验工作树的 `pr-review-response` 指令。调用方已加载这些指令时直接复用。仅复用本技能的提交前检查、验证和推送步骤时，无需准备监控流程。

1. **提交前检查**：检查 status、diff（含格式检查）、近期提交、分支和远端，确认提交范围与 PR 目标。若在 `main`，加载 `new-worktree` 并按其工作树准备步骤切换 DSH 会话。先确认本任务改动的迁移范围和方式。切换失败或本任务改动尚未核验到位时，停止提交。保留他人及无关改动。
2. **确认工单**：只使用用户明确提供或上下文已明确关联的工单，核验存在且语义相符；歧义或不符时询问，不搜索、推断或改挂工单。没有关联工单则省略 `Closes` 和工单回复。
3. **验证**：先运行相关测试，可行时执行完整测试；未执行或失败的验证如实说明，不报告为通过。
4. **提交并推送**：准备创建 PR 时，先确认切换前加载的监控与工作树核验指令仍在当前上下文中。无法取得指令时停止交付并报告，直到流程可用再推送或创建 PR。只暂存已获认可的文件，按仓库规范使用约定式提交。没有上游时设置跟踪。未经明确要求，不 amend、跳过钩子、强推或更改 Git 配置。
5. **创建 PR**：使用可用的 `gt` 或 `tea` 创建 PR；head 为工作分支，base 为仓库默认分支，用户指定时从其要求。正文包含摘要与验证结果，仅在明确关联且应随合并关闭的工单上使用 `Closes #N`。
6. **回复关联工单**：仅在 PR 创建后使用可用的 `gt` 或 `tea` 回复已明确关联的工单，附 PR URL、完成内容、测试结果与工程结论，使用真实换行；不手动关闭工单。
7. **监控 CI**：使用切换前保留的 `watch-pr-ci` 指令，以本次创建的 PR URL 为目标，处理失败并监控至完成，不自动合并 PR。
8. **核验交付**：确认 PR 开启且 head/base 正确，核验工单回复（如有）、本地与远端同步及剩余改动，向用户返回 commit hash、PR URL 和 CI 结果。

## 回归场景

从包含迁移的工作树启动交付，再切到没有 `watch-pr-ci` 的基线。预期推送前确认原有指令仍可用，创建 PR 后继续用它监控。如果缺少必要指令，在推送或创建 PR 前报告并停止。

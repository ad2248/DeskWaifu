# 按已确认计划实施并交付

根据当前会话中已经与用户确认的任务目标、实施计划、验收标准及最新约束，继续完成任务并提交交付。遵循本次调用附带的补充要求。

在切换工作树前，从当前工作树加载并保留 `submit-code-and-pr` 及其要求的监控和工作树核验指令。实施和验证完成后再执行交付。

1. 从当前会话恢复已谈好的目标和计划，简要确认本次实施范围与验收标准，不要求用户无故重复提供，也不重新规划已确认的方案。若缺少必要上下文，或补充要求与原计划存在实质冲突，先询问用户，不自行猜测。
2. 阅读适用的 `AGENTS.md`，检查工作区、当前分支、远端及基线。若仍在 `main`，在修改代码前加载 `new-worktree`，按其中的工作树准备步骤创建专用工作树并切换 DSH 会话。若任务依赖原工作树中的未提交改动，先确认迁移范围和方式，核验改动到位后再实施。切换失败时停止。已处于合适的专用工作树时复用。保留无关改动。若分支相对 PR 基线包含不属于本任务的前置提交，先确认它们已合并，否则询问用户如何处理。
3. 按已确认的计划实施必要的最小改动，保持仓库风格。修复缺陷时补充回归测试，逐项核验验收标准；不要只输出方案、创建工作树或描述下一步就结束。
4. 运行最小相关验证，可行时再运行完整回归；检查最终 diff，确认只包含本任务改动。必需测试失败、目标尚未完成或存在必要信息缺口时，先修复或明确报告阻塞，不将未完成任务当作已完成提交。未执行或因环境跳过的验证必须如实说明。
5. 实施及验证完成后，若用户既未显式调用本技能，也未要求提交交付，则汇报实施与验证结果。其余情况按已加载的 `submit-code-and-pr` 指令交付，完成该 skill 要求的提交前检查、仅暂存本任务文件、中文约定式提交、推送、创建 PR 及交付核验，不以口头建议用户另行执行提交代替操作。没有本任务改动时，不创建空提交或空 PR；若 skill 无法加载或交付操作失败，报告实际完成阶段与阻塞原因，不绕过限制或谎报成功。
6. 仅使用用户明确提供或当前上下文已明确关联的工单。没有关联工单时，不搜索或推断潜在关联，不添加 `Closes` 声明，也不回复或关闭任何工单。
7. 最后汇总完成的目标、实际验证结果、commit hash 和 PR URL，并确认工作区及上游同步状态；仍有未完成事项时明确列出。

全程沿用当前会话模式、权限和用户明确的操作限制。Plan 模式下只做分析和规划。强推、重置他人改动、合并 PR 或扩大任务范围均须另行授权。

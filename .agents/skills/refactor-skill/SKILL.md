# 审查并重构 Skill

定位目标 Skill 文件，完成问题诊断后**直接修改文件**，在不丢失任何硬约束的前提下最大化信噪比与执行稳定性。

## 执行步骤

1. **定位目标**：若未指定目标 Skill 路径，先询问再执行。读取目标文件及同目录下关联脚本。
2. **排查问题**：按以下 4 项标准逐一审查：
   - **脚本化边界**：识别用自然语言硬写的复杂确定性操作（如精细 Git 状态迁移、批量校验与回滚）。
   - **单一职责**：剔除应归属全局 `AGENTS.md` 的通用开发规范，以及混入正文中的测试用例、回归场景和背景废话。
   - **去冗余**：合并重复的防御性措辞（如反复出现的“失败则停止并报告”），收拢为单条异常处理原则；删去常识性微操。
   - **硬约束显性化**：将藏在长段落里的路径模板、命名规范、工具优先级与回退条件，提炼为清晰的清单或表格。
3. **抽离脚本（按需）**：若存在应脚本化的确定性逻辑，在 Skill 同目录 `scripts/` 下创建独立可执行脚本（明确入参与非零退出码），并在 Skill 正文中替换为简洁的调用说明。
4. **直接改写**：直接覆盖更新目标 Skill 文件。改写必须完整保留原有的核心硬约束与不可逆操作的安全边界。
5. **汇报变更**：用简短清单说明：
   - 删减/合并了哪些冗余或越界内容；
   - 抽离了哪些脚本及路径（如有）；
   - 保留了哪些关键硬约束供核对。
